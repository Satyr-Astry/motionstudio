# 合流计划：对象层级与画板笔刷（2026-10 第十八批）

> 本文把三份计划的未完成部分并成一条执行线：①本轮「对象栈层级 / 拖拽 / UI」规格 ②`docs/下一步计划-2026-10.md` 里还欠的第一批条目 ③`docs/待修与优化清单-2026-10.md` 里剩下的鲁棒性 P2。
> 已完成的批次（画板图标化、项目管理、纹理像素尺寸、适配提示）不在本文重复。

## 0. 结论先行

- 对象栈的问题不是"少个拖拽"，而是**一次拖拽同时改了层级和位置**，并且**界面从不显示层级**。所以顺序是：先让"换父级不跳位"，再让"层级看得见"，最后才是"拖得准"。
- 多层嵌套在数据模型里已经成立（`parentId` 单链，核心求值链上限 64）。这一批只补界面与交互，不改模型。
- 版本号从这一轮起重排：见 §5。

## 1. 本批要做（按依赖顺序）

### L1 · 换父级保住画面位置（核心）

现在 `setParent`（`app/core/timegraph.mjs:263-285`）只改 `parentId`，不换算坐标，松手对象就跳进父坐标系。

要做：换父时用新父矩阵求逆重算该对象 `x/y`，其余 transform 分量不动；矩阵不可逆（父含斜切/非均匀缩放退化）时拒绝并给原因，不静默跳位。脱离父级（`parentId → null`）同样处理。

验收：已旋转 30° 的对象拖进另一个对象后，画面逐像素不动；`Ctrl+Z` 一步同时回到旧层级与旧位置。

### L2 · 面板按树显示（层级看得见）

缩进其实已经有了：`app/editors/layers.mjs:549-555` 用 `ctx.layerDepth(id)` 算 `padding-left = 6 + depth*12` 并加 `.is-child`。缺的是**六件**：①遍历不是深度优先（父可能排在子后面，缩进于是看起来是错的）②竖向引导线 ③「N 个子对象」胶囊 ④子行缩略图 28→22 ⑤`Alt+点箭头` 只折一支 ⑥空态文案。

要做：按 `parentId` 深度优先渲染（父在前、子紧随）；每级缩进沿用现有 12px，超过 6 级折成 `+N`；竖向引导线 1px `--line` 50% 只画到同层最后一行；有子对象的行尾加「N 个子对象」胶囊（10px `tabular-nums`）；子行缩略图 28→22（名称字号不变）；折叠沿用 `ms.layers.collapsed`，`Alt+点箭头` 只折/展这一支；空态 `没有对象 · 用 ＋ 新建，或把 PSD / 图片拖进窗口`。

验收：任意三层嵌套对象的缩进、引导线、子计数正确；父排在子前的顺序在任意拖拽后仍成立；折叠父行后子孙全部隐藏；三尺寸（1680/1280/1000）无截断、无横向溢出。

### L3 · 三区拖拽与落点预览（拖得准）

现在只有"行左 45% 调顺序 / 右 55% 当子对象"（`layers.mjs:248-269`），落点靠猜，没有"插到前后"，也不能拖到空白解除父子。

要做：行上缘 25% = 插到该行前、下缘 25% = 插到该行后（同级兄弟）、行中 50% = 投进该行当子对象、列表空白 = 移到根层末尾；实时插入线（2px `--accent` + 左端 3px 圆点，按目标层级缩进）与目标行高亮（`--sel-bg-strong` + 1px 虚线 `--accent`）；非法目标（自身/自己的后代）用 `--danger` 淡底 + `not-allowed`；拖父对象时整棵子树一起移动，行尾标"含 N 个子对象"；拖到列表上下边缘自动滚动。

实现约束：`reorderObject`（`app/core/doc-model.mjs:788-798`）现在是单对象 splice，需要支持"按子树插入"，并保持"父在子前"的连续性。

**新增的原子接口（本批新定，L1 线实现）**：`ctx.moveSubtree(id, { mode: 'before'|'after'|'into'|'rootEnd', targetId })` → `boolean`。一次 `setDoc` 完成「换父 + 子树整体搬位」，保证父在子前；`mode:'into'` 内部必须复用 L1 的保位置换算。`layers.mjs` 侧先用 `typeof ctx.moveSubtree === 'function'` 探测，没有就降级成 `setLayerParent` + `moveLayerTo` 两步（撤销会多一步，属降级路径）。子树计算直接复用 `app/core/timegraph.mjs` 已有的 `collectSubtree`(:326) / `subtreeSize`(:352) / `rootLayers`(:357) / `detachChildren`(:363)，别另写一套。

### L4 · 键盘与撤销

`Alt+↑/↓` 同级重排、`Alt+→` **缩进**（成为前一个兄弟的子对象）、`Alt+←` **提升**（成为父的兄弟，插在父之后）、`Esc` 取消拖拽；一次拖拽 / 一次键盘动作 = 一条撤销记录。键位写进 `help.mjs`（该文件单一责任人不变）。

**方向口径（已按实测定稿，别再翻）**：按「在树上走」的直觉 —— **→ 往里、← 往外**。这与 `app/core/layer-order.mjs` 里 `demoteTarget` / `promoteTarget` 的**命名顺序相反**（那是数据侧的名字），`layerKeyTarget` 因此一度把 `left` 接到 `demote` 上，真机被 icon-system 读数抓住（`Alt+←` 实际在做缩进）。修正后 `layerKeyTarget('right') → demoteTarget`、`layerKeyTarget('left') → promoteTarget`，两处测试（`tests/layers-keys.test.mjs`、`tests/layer-keys.test.mjs`）都钉了这个方向。真机复核：`p,q,r` → `Alt+→` → `p,q<p,r` → `Alt+←` → `p,q,r`。

**撤销粒度**：`setDoc` 默认「350ms 手势合并」，连按两下 `Alt+↑` 会被并成一条撤销（按三下只退一次）。因此 `ctx.moveSubtree` 多了可选 `coalesce` 透传，键盘每次按键传一个不同键（`layer-keys-<n>`），拖拽不传、仍走默认合并。

### L5 · 属性面板承认父子关系

"对象"组补两行：「父对象：X」（点击跳到该对象）+「脱离父级」按钮；子对象悬停说明继承了什么（时间通道 / 不透明度 / 显示 / 混合模式 / 变换）。

### B1 · 画板压感接线（来自上一轮计划第一批第 1 条，代价 S）

`app/paint/engine.mjs:399-402 pressureOf` → `:485/:567/:581 stampAt(x,y,p)` 整条链路已带压感，**只有画板路径没接**：`app/editors/board.mjs` 的 `stamp(g, img, x, y, alpha)`（约 `:720`）没有 pressure 参数。照抄引擎侧写法即可。

验收：同一条手绘轨迹，压感关/开两档的笔迹宽度分布可测（给出中位数与四分位）；不动引擎侧行为。

### B2 · 画笔间距重标定（第一批第 2 条，代价 S）

我们 `app/paint/brush.mjs:33` 的 spacing 是"笔尖直径的倍数"，Klecks 的 `size` 是半径（`pen-brush.ts:189 arc(x,y,size)`、`:235 size*settingSpacing`），换算后**差 3.5 倍**（软笔 5.3、散点 8.5）。要做：按 Klecks 口径重标定 7 支笔的默认 spacing，保留旧值可通过 `localStorage['ms.brush.'+id]` 覆盖。

验收：圆笔默认间距与 Klecks 对齐（0.8489·R），给出重标定前后"半透明笔连续笔画是否有断珠/是否过快变实色"的对照读数。

### R1 · 剩下的鲁棒性 P2（来自待修清单）

- `app/shell/doc-state.mjs` 的 `setDoc` 抛错目前只 `console.error`：改成会提示用户（同一句话，不弹窗）。
- 父子环导致对象静默消失：渲染层给"数据异常"占位并发一次提示（环由 `setParent` 拦住，但手改存档能出现）。
- `docShell` 不写 `duration` 与 `createDocument` 形状不一致：补齐字段（只写默认值，不改语义）。

## 2. 本批不做

跨文档拖拽、多选批量拖拽、独立"组"对象类型、时间轴上的层级联动、笔刷其余条目（笔尖 4 形状 / 多 pass 平滑 / smudge / Bresenham / Blend / Sketchy / 预设多套）、选区、WebM alpha、PSB 智能对象与文字层。

## 3. 验收总表

1. 换父级/脱离父级：画面逐像素不动，一步撤销。
2. 面板：三层嵌套的缩进、引导线、子计数、折叠都正确；三尺寸 `clipping/small/truncation` 全 0。
3. 拖拽：四个落点（前/后/内/根末尾）与最终数组下标一致；非法目标被拒；拖父带子。
4. 键盘：`Alt+↑↓←→` 与 `Esc` 行为符合 §L4；`help.mjs` 键位表同步。
5. 笔刷：压感在画板生效、间距按新口径；给对照读数。
6. 全量测试绿、`_check-static.mjs` 干净、真机三尺寸审计全 0。

## 5. 版本号规则（重排）

现状是一串互不成体系的标签：`v0.0.1-alpha`、`v0.0.1-alpha.2`…`v0.0.1-alpha.6`，另外还留着更早的 `v1.0.0`、`v1.0.0-beta.1`。测试阶段要能一眼看出"这是第几批、修到第几版"。

新规则（本文生效）：

- 形式 `0.<批次>.<修订>-alpha.<序号>`，例 `0.1.0-alpha.7`。
- **批次**（第二位）：每完成一轮成批的用户可见功能 +1。本轮 = `1`。
- **修订**（第三位）：只修 bug、不加功能时 +1；加功能时归零。
- **alpha.序号**：预发布计数，**全局单调递增、不随批次重置**，每次打标签 +1。
- 标签一律 `v<version>`，与本文件对应的发布说明写在 `CHANGELOG.md` 顶部。
- `v1.0.0` / `v1.0.0-beta.1` 保留为历史标签，不参与新规则；`0.0.1-alpha.*` 视为"脚手架期"，从 `0.1.0-alpha.7` 起进入"可用期"。
- 出正式版的条件写死在这里：连续 3 个批次没有阻塞级缺陷、导出链路有自动化回归、Windows 之外至少一个平台验证过，才发 `1.0.0`。
