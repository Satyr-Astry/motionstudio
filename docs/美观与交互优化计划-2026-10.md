## 2. 八类条目

### ① 层次与留白

#### A1 间距阶梯断档：只有 4 档、最大 8px

- **现状**：`tokens.css:89-92` 只有 `--sp-1 2 / --sp-2 4 / --sp-3 6 / --sp-4 8`；`panels.css` 里 140 处 `padding` 声明没有任何一处 ≥10px 的令牌可用，只能手写 px（截图 `final-timeline.png`：属性面板 5 个分组之间是 1px 线，组与组几乎贴在一起）。
- **参照**：Fluent 2 的间距阶梯是 4/8/12/16/20/24；Linear 的面板内边距固定 12、分组间距 16。两者共同点是**存在 ≥12px 的一档**，才有「组」的视觉边界。
- **改法**：`tokens.css` 加 `--sp-5 12px / --sp-6 16px / --sp-7 24px`；先只用在 3 个位置：面板内边距（`.area-body`）、属性组分隔（`.prop-group`）、浮层内边距（`.cmd-*`）。其余暂不动。
- **代价**：L（令牌加 3 行是 S，但「逐处判断哪些该放大」是 L —— 涉及 6 个面板的取舍）
- **收益**：属性面板 5 组、设置 4 面板、命令面板 42 行获得一致的组间距；视觉层次从「只有分割线」变成「线 + 空隙」双信号。
- **阶段**：三（先出方案，见 G3）

#### A2 面板浮不起来：`--panel` 与 `--bg` 只差 13% 亮度，且没有高光/投影

- **现状**：画布区背景 `--bg #141518`，面板 `--panel #212328`；两者之间只有 `--line` 的 1px 边（`final-timeline.png`：面板与画布的分界几乎看不出，靠对象面板的灰色块才认出边界）。
- **参照**：Linear 的侧栏用「1px 半透明白高光 + 1 层极淡投影」把面板从画布上抬起来；Vercel 的卡片同理。两者都不靠加深底色。
- **改法**：`panels.css` 给 `.area` 加 `box-shadow: inset 0 1px 0 rgba(255,255,255,.03)`；`.area` 与画布之间改用 `--line-2`。
- **代价**：S（2 条规则，纯视觉，可秒回滚）
- **收益**：6 个面板一次性获得「浮层」感，不增加任何色值令牌。
- **阶段**：一

#### A3 属性面板 5 个分组之间只有 1px 线

- **现状**：`final-timeline.png` 属性面板依次是「对象 / 变换 / 网格变形 / 效果 / 工程」，组标题 `.prop-group` 高 `--h-bar 26px`，组间无间距；`(截图) …效果 / 工程` 之间视觉连成一片。
- **参照**：Photoshop 属性面板组间距 8px、组内 2px；Blender 属性面板用「面板卡片 + 8px 间隙」。
- **改法**：`panels.css` 的 `.prop-group + .prop-group` 加 `margin-top: 6px`（先用 `--sp-3`，等 A1 落地换 `--sp-2`+`--sp-3` 组合）。
- **代价**：S（1 条规则）
- **收益**：属性面板 5 组、设置 6 组，边界从「1 条线」变成「线 + 6px」，分组可数。
- **阶段**：一

#### A4 顶栏右侧 300px 空白

- **现状**：`final-timeline.png` 顶栏从左到「设置」页签结束在 x≈670，右侧到 1680 全空（约 1000px 空白，其中约 300px 是「本可以放东西的位置」）。
- **参照**：Linear 把「命令面板入口（⌘K）」固定在顶栏右侧；Figma 右侧放「分享/演示」。
- **改法**：`chrome.mjs` 在 `.top-ws` 之后加一个 `⌘K` 样式的按钮，点击等价 `Ctrl+Shift+P`（命令面板已有，只是入口在快捷键里）。纯图标 + 文字，复用 `icon('search')`。
- **代价**：S（1 个按钮 + 1 处事件接线）
- **收益**：命令面板从「只有知道快捷键的人能用」变成「看得见」，34 条命令的发现成本从 0 次点击（知道）变成 1 次点击（不知道也能找到）。
- **阶段**：三（涉及顶栏布局取舍）

#### A5 画布与面板之间没有视觉缓冲

- **现状**：canvas 1144×716 与 layers 232 / properties 292 之间只有 1px `--line`；`final-board.png` 里画板工作区更极端 —— 画布 762×562 直接贴着左列 232，无任何间距。
- **参照**：Aseprite 的 canvas 与时间轴之间保留 1px 深色缝；Figma 的画布用 `--bg` 最深色包住编辑器面板，形成「画布是舞台」的观感。
- **改法**：与 A2 合并做（同一个 `box-shadow` + 描边方案），不单列规则。
- **代价**：S（并入 A2）
- **收益**：见 A2。
- **阶段**：一（并入 A2）

### ② 选中与悬停态

#### B1 95 个 hover 里只有 5 个有过渡

- **现状**：`transition` 声明 5 条（`tokens.css:201/336/349`、`panels.css:635/641`），`:hover` 95 条。典型：`.lyr-row:hover { background: var(--panel-2) }`（`panels.css:449`）无过渡 → 鼠标扫过对象列表时底色瞬跳。
- **参照**：Figma 的所有 hover 都是 80–120ms ease-out；Linear 用 100ms。
- **改法**：`panels.css` 给 `.lyr-row` / `.fx-add > button` / `.area-btn` / `.top-file-btn` / `.bd-brush` / `.curve-preset` 六处 hover 补 `transition: background-color var(--t-fast), border-color var(--t-fast)`。
- **代价**：S（6 条声明，纯 CSS）
- **收益**：hover 有过渡的比例从 5.3% 提到 ~11%；覆盖对象列表行、5 个效果胶囊、区域头 3 按钮、顶栏 8 按钮、画板 7 支笔、曲线 6 预设。
- **阶段**：一

#### B2 全站只有 3 条 `:active`，按钮按下没有反馈

- **现状**：`:active` 3 条 / 113 个可交互控件 = 2.7%。实测点击 `top-file-btn`、`bd-brush`、`tline-btn` 时背景不变、位置不变。
- **参照**：Fluent 2 的 pressed 态定义是「背景加深一级」（不是缩放）；Figma 用 `scale(0.98)` + 80ms。
- **改法**：`tokens.css` 加一条通用规则 `button:active:not(:disabled), .bd-brush:active { background: var(--surface); }`，另给图标按钮加 `transform: scale(.98)`。
- **代价**：S（2 条规则，覆盖全部按钮）
- **收益**：113 个控件一次性获得按下反馈；这是「有没有反馈」的从 0 到 1，不是程度问题。
- **阶段**：一

#### B3 选中态用了三套互不一致的视觉

- **现状**：三种选中表达同时存在 —— `.top-ws-tab.is-on` 实心蓝底（截图顶栏「编排」）、`.lyr-row.is-sel` 16% 蓝底 + 2px 左侧条（`panels.css:858-860`）、`.xf-segbtn.is-on` 实心蓝底 + 深色字。`.is-on/.is-sel/.is-active` 共 33 条规则。
- **参照**：Figma 的约定很清楚 ——**实心填充 = 开关/模式**（当前工具、当前页签），**浅底 + 边框 = 列表选中项**，两者不混用。
- **改法**：把 33 条规则归成 2 个语义类（`.is-toggle` / `.is-select`），CSS 侧合并选择器；渲染侧只在 `layers.mjs`、`xform.mjs`、`timeline-paint.mjs`、`chrome.mjs` 四处改类名。
- **代价**：M（4 个渲染点 + CSS 合并）
- **收益**：33 条规则收敛到 2 套；用户不用再猜「蓝色实心」是「开着」还是「选中」。
- **阶段**：二

#### B4 关键帧 hover 色硬编码，脱离令牌

- **现状**：`.tline-kf:hover { background: #7fa0ff }`（`panels.css:872`）—— 全站唯一的裸色值之一，与 `--accent #4a7dff` 同族但不是令牌。
- **参照**：Linear 的所有 hover 色都由令牌派生（`color-mix` 或独立变量），不写裸值。
- **改法**：`tokens.css` 加 `--accent-hover: #7fa0ff`，`panels.css:872` 改用它。
- **代价**：S（2 行）
- **收益**：裸色值 -1；将来换主题时这个点不会漏。
- **阶段**：一

#### B5 焦点环在蓝底按钮上不可见

- **现状**：`--focus-ring: 1px solid var(--accent)`（`tokens.css:96`），`:focus` 16 条。在 `.top-ws-tab.is-on`（蓝底）上，蓝环与蓝底同色 → 键盘用户看不出焦点在哪。
- **参照**：Figma 用「内 1px 白 + 外 1px 蓝」双层焦点环，任何底色上都可见。
- **改法**：`:focus-visible` 改成 `box-shadow: 0 0 0 1px var(--bg), 0 0 0 2px var(--accent)`。
- **代价**：S（1 条规则）
- **收益**：16 处焦点态在深底/蓝底上都可见；这是可访问性缺口，不只是美观。
- **阶段**：三（与 B3 一起做，避免和选中态规则打架）

### ③ 数字与单位对齐

#### C1 同一件事两种写法：信息面板 `900 X 640`，属性面板 `900 × 640`

- **现状**：`final-settings.png` 右侧信息面板「画布尺寸 `900 X 640`」用拉丁大写 X；`final-timeline.png` 属性面板尺寸行用乘号 `×`。同一屏两个面板，两种符号。
- **参照**：Photoshop/Aseprite 的尺寸读数统一用 `×`（U+00D7）。
- **改法**：`prop-info.mjs` 里那处拼串改成 `×`。
- **代价**：S（1 处字符串，但要改 JS）
- **收益**：数值写法归一到 1 种；涉及信息面板 5 行读数中的 1 行。
- **阶段**：二

#### C2 状态栏右段开头多一个 `·`

- **现状**：实测 `.stb-right` 的 `textContent` 是 `· t 0.00 s · 帧 0/12 · 对象 1 · 编排`；渲染出来是 `· · t 0.00 s`（`final-timeline.png` 右下角能看到连续两个点）。
- **参照**：Aseprite 状态栏固定 3 段，段内不用分隔符，用间距分隔。
- **改法**：`chrome.mjs` 拼串去掉首项前导 `·`（改成 `arr.join(' · ')` 而不是每项前拼 `· `）。
- **代价**：S（1 行）
- **收益**：去掉 1 个多余的视觉噪点；状态栏右段 4 项归位。
- **阶段**：二（动 JS）

#### C3 状态栏两段同色同字号，没有主次

- **现状**：`.stb-left` 与 `.stb-right` 都是 `11px` + `--ink-dim`（`shell.css:76-92`），左段还是 ` · ` 串起来的 5 项（画板工作区实测：`900×640 · 1 对象 · 12 fps · 画笔 8px · 100%`）。
- **参照**：Aseprite 状态栏只显示 3 项核心数字，其余进 tooltip；Blender 状态栏把「当前操作提示」用高亮色、把读数用弱色。
- **改法**：`chrome.mjs` 把左段拆成分段 span（`.stb-kv > .stb-k + .stb-v`），CSS 里键用 `--ink-faint`、值用 `--ink`；`fps` 与 `画笔 px` 这类「会变化的数字」用 `--ink`，其余 `--ink-dim`。
- **代价**：M（渲染 + CSS 两侧，涉及画板/编排两套状态栏文案）
- **收益**：状态栏 2 段 9 项获得 3 级文字层次；用户扫一眼能找到「帧率」和「笔尖大小」。
- **阶段**：二

#### C4 「尺寸」空输入框是凹陷的弱控件

- **现状**：实测 `input.prop-num` 92×20，底色 `--bg #141518`（比所在面板 `--panel #212328` **更暗**）、边框 `--line #33363d`、placeholder `--ink-faint`（对底 **3.6:1**，低于 AA 4.5:1）。空值时整个控件像一块暗斑（`final-timeline.png` 尺寸行两个框）。且它**没有单位、没有标签**（只有 placeholder「宽/高」）。
- **参照**：Photoshop 的输入框是「比面板亮一级的底 + `--line-2` 边框 + 右侧单位标签」；Fluent 2 的 TextField 底比容器亮 1 级（凸起），不用凹陷。
- **改法**：`tokens.css` 输入基座改 `background: var(--surface)`、`border-color: var(--line-2)`、`::placeholder { color: var(--ink-dim) }`；单位在 JS 里补（与 C5 一起）。
- **代价**：S（3 行令牌级改动，全站输入框一起变亮）
- **收益**：全站约 28 个 `prop-num`/`xf-num` 输入框从「凹陷暗斑」变「可编辑控件」；placeholder 对比度 3.6 → 6.5:1。
- **阶段**：一

#### C5 单位写法不统一

- **现状**：`100 %`（带空格）、`12 fps`（带空格）、`t 0.00 s`（带空格）、`900 × 640`（无单位）、`画笔 8px`（无空格）。同一屏（状态栏）里 `12 fps` 与 `画笔 8px` 两种风格并存。
- **参照**：Aseprite 把单位跟数字紧贴（`12fps`、`8px`）；Photoshop 把单位单独成列。
- **改法**：定一条规则「单位跟随数字，中间不加空格」（`12fps` / `8px` / `100%` / `0.00s`），在 `chrome.mjs`、`timeline-paint.mjs`、`prop-body.mjs` 三处模板串里统一。
- **代价**：M（散在 3 个文件的模板串）
- **收益**：状态栏 + 属性面板 + 时间轴读数共约 12 处写法归一到 1 种规则。
- **阶段**：二

#### C6 数字框的 `tabular-nums` 只覆盖了一部分

- **现状**：`input`（`tokens.css:260` 注释说明等宽数字）与 `.stb-right`（`shell.css:90`）有 `font-variant-numeric: tabular-nums`；但时间轴读数 `.tline-now/.tline-total`（48×20）与 `.xf-num` 未见声明，播放时数字宽度变化会让内容左右抖。
- **参照**：Aseprite 的时间码永远等宽，不抖。
- **改法**：`panels.css` 给 `.tline-now, .tline-total, .xf-num, .prop-num` 补 `font-variant-numeric: tabular-nums`。
- **代价**：S（1 条规则）
- **收益**：4 类数字框在数值变化时不再抖动；播放 12fps 时每秒抖 12 次的问题消失。
- **阶段**：一

### ④ 空态与引导

#### D1 属性面板「该对象还没有效果」是 2.9:1 的裸文字

- **现状**：`.fx-empty { font-size: 11px; color: var(--ink-faint); padding: 2px 0 4px }`（`panels.css:992-994`），文案「该对象还没有效果」（`prop-object.mjs:135`）。对 `--panel` 底 **2.9:1**，低于 AA。
- **参照**：Figma 的空面板用「24px 图标 + 一句引导 + 一个主行动」；Linear 的空态用 `--ink-dim` 而不是最弱一级。

- **收益**：空态对比度 2.9 → 6.5:1；「效果」组的空状态也能认出是「组」而不是「分隔线」。

### ⑤ 动效与反馈

#### E1 过渡令牌用 `linear`，这是手感最廉价的一种曲线

- **现状**：`--t-fast: 80ms linear`（`tokens.css:95`）。`linear` 在 80ms 尺度上会被感知为「啪」地跳到位，没有加速减速。
- **参照**：Fluent 2 的标准曲线是 `cubic-bezier(0.33, 0, 0.67, 1)`（ease-out 类）；Material 的 standard 是 `cubic-bezier(0.2, 0, 0, 1)`；Linear 用 `cubic-bezier(.2,0,.2,1)` 配 100ms。
- **改法**：`tokens.css:95` 改 `--t-fast: 120ms cubic-bezier(.2, 0, .2, 1)`。
- **代价**：S（**1 行**）
- **收益**：现有 5 条 transition 立刻改观，且将来所有 `var(--t-fast)` 引用自动受益；这是全文档性价比最高的一条。
- **阶段**：一（第一条做）

#### E2 没有 `prefers-reduced-motion` 分支

- **现状**：全仓 `prefers-reduced-motion` 0 命中。一旦按 E1/B1/B2 加动效，对动效敏感的用户没有退路。
- **参照**：Linear/Vercel 都在加动效的同一个 PR 里加这条 media query。
- **改法**：`tokens.css` 末尾加 `@media (prefers-reduced-motion: reduce) { :root { --t-fast: 0ms linear } }`。
- **代价**：S（3 行）
- **收益**：动效开关 1 处集中控制，不用逐个选择器写。
- **阶段**：一（与 E1 同批）

#### E3 面板折叠/展开是瞬变

- **现状**：区域折叠由 `view-host.mjs` 切 `display` 实现，无过渡；`final-settings.png` 里 4 个面板的折叠三角形点下去是瞬间消失/出现。
- **参照**：Blender 的属性面板展开是 120ms 的高度过渡；VS Code 的侧栏折叠同理。
- **改法**：纯 CSS 方案 —— `.area-body { display: grid; grid-template-rows: 1fr; transition: grid-template-rows 120ms }` + `.area.is-collapsed .area-body { grid-template-rows: 0fr }`，JS 只切类名（不改 `display`）。
- **代价**：M（要动 `view-host.mjs` 的折叠逻辑 1 处，且需验证不影响内联尺寸的面板）
- **收益**：6 个区域面板的折叠有了方向感；避免「点了一下不知道发生了什么」。
- **阶段**：二

#### E4 关键帧菱形拖动时没有「抓住」反馈

- **现状**：`.tline-kf:hover { background: #7fa0ff }`（`panels.css:872`），只变底色；拖动中无缩放、无描边。菱形本身 7×7（`KF_SIZE 7`），是屏幕上最小的可交互元素。
- **参照**：Aseprite 的帧块在被抓取时描边变亮；Figma 的控制点拖动时加外发光。
- **改法**：`.tline-kf.is-drag { box-shadow: 0 0 0 2px rgba(74,125,255,.35) }`，`timeline.mjs` 在 pointerdown 时加类。
- **代价**：S（1 条 CSS + 1 行加类）
- **收益**：7×7 的关键帧在拖动中「变大」约 11×11 的视觉面积，命中确认感提升。
- **阶段**：二

#### E5 无 loading / 进度反馈

- **现状**：导出帧序列、PSD 导入这类耗时操作（`final-board.png` 的 toast 是「完成」提示）没有中间态；用户点完「导出帧序列」后没有任何「正在生成」的信号。
- **参照**：Linear 的所有异步操作都有 200ms 延迟后出现的细进度条；Figma 导出显示「3/12」。
- **改法**：`export*.mjs` 在循环里更新状态栏左段文字（`导出 3/12`），复用 C3 的分段 span。
- **代价**：M
- **收益**：12 帧导出从「黑箱」变成「有进度」；与 C3 共享同一套状态栏结构。
- **阶段**：二（依赖 C3）

#### E6 toast 位置固定在顶栏右上，与操作发生地无关

- **现状**：`final-board.png` 的「已新建纹理并绑定到当前时刻」出现在顶栏右侧（y≈16），而触发它的「+ 纹理」按钮在画布右上角（y≈76）；`w3f-split-1000x620.png` 里它同样在右上。
- **参照**：Figma 的 toast 从底部中间弹出；Linear 从右下。共同点是**远离顶栏**，因为顶栏已有大量信息。
- **改法**：`view-host.mjs` 的 toast 容器改挂到 `#statusbar` 上方（绝对定位 `bottom: 24px`），或右下角距边 16px。
- **代价**：S（1 处容器位置）
- **收益**：toast 与顶栏页签不再抢同一视觉带；1 个调试点位。
- **阶段**：二

### ⑥ 图标一致性

#### F1 三档图标 stroke 固定 1.6，视觉重量随尺寸漂移

- **现状**：`icons.mjs` 统一 `stroke-width = 1.6`（24×24 坐标系）。换算到实际像素：14px 档 = 0.93px、16px 档 = 1.07px、28px 档 = **1.87px**（是 14 档的 2 倍）。唯一处理过的 28px 用例是在 `project-io.mjs:497` 里内联把 stroke 改成 1.4 —— 那是**JS 里的字符串 CSS**，不是令牌。

- **改法**：`icons.css` 加两条 `[data-size="sm"] { stroke-width: 1.85 }`、`[data-size="lg"] { stroke-width: 1.35 }`，使三档视觉宽度收敛到 1.07 / 1.08 / 1.58px；同时删掉 `project-io.mjs:497` 的内联覆盖。
- **代价**：S（2 条 CSS + 删 1 处字符串）
- **收益**：51 个图标 × 3 档视觉重量统一；28 档的例外从 JS 回到 CSS。
- **阶段**：一

#### F2 `--icon-lg` 全站只有 1 处用例，是「为了一处存在的令牌」

- **代价**：S
- **收益**：消除「零使用率令牌」；减少维护面。
- **阶段**：一（若选 (b)）／三（若选 (a)，涉及新界面）

#### F3 图标与文字基线已对齐，这条作为**已解决**记录

### ⑧ 字体与字号

#### H1 10px 有 37 处声明，最密的是时间轴

- **现状**：10px ×37 声明（CSS），实算命中 38 个元素。典型：时间轴刻度尺 `0.0s 0.1s …`（10px，`timeline-paint.mjs` 内联）、段条 `12fps`（10px，段条高 `FPS_H 12px`）、键帽 `.kbd`（10px）。
- **参照**：Aseprite 的时间轴用像素字体但在 200% 缩放渲染；Figma 全站最小 11px。10px 在现代高 DPI 屏上可读，但在 100% 缩放下等宽数字的横杠会糊。
- **改法**：只把「刻度尺」从 10px 提到 11px（`timeline-paint.mjs` 一处内联 + `RULER_H 30px` 有余量），段条与键帽保持 10px。
- **代价**：S（1 处内联字号；需真机复核刻度标签不重叠 —— 刻度间距 `SEC_PX 28px`，11px 下 `0.1s` 约 22px 宽，安全）
- **收益**：时间轴最常读的 12 个刻度标签可读性提升；不动 `FPS_H`（刚在 task-14 定过 12）。
- **阶段**：二（动 JS 内联）

#### H2 字号阶梯缺 14/16，组标题与正文差 1px

- **现状**：11px ×76 / 12px ×15 / 13px ×3；实算 16px 只有 1 个元素。组标题 `.prop-group` 与正文都是 11px（只有颜色差），面板标题 12px。
- **参照**：Fluent 2 的阶梯 10/12/14/16/20；Linear 用 11/13/15 三档且**标题比正文大 2px + 字重 500**。
- **改法**：组标题 11 → 12px + `font-weight: 500`；面板标题 12 → 13px。共约 8 处声明。
- **代价**：S（CSS）
- **收益**：属性面板 5 组、设置 6 组标题从「同字号不同色」变成「大 1px + 粗一档」，层级不用靠颜色猜。
- **阶段**：一

#### H3 全站只有 7 处 `font-weight`，层次全靠颜色

- **现状**：`font-weight` 声明 600×4 / 500×1 / 400×1 / 700×1。`.lyr-name`、`.prop-label`、`.stb-left` 全是默认 400。
- **参照**：Linear 的标题 500、正文 400、弱化 400（只靠色）；Figma 用 500 做所有区块标题。
- **改法**：与 H2 合并 —— 组标题、面板标题、对象名（选中时）用 500。
- **代价**：S（4–6 处）
- **收益**：字重成为第 2 个层次信号，减少对 `--ink-faint`（2.9:1）的依赖。
- **阶段**：一（与 H2 同批）

## 5. Lead 点名的六项：逐条回应

| 点名项 | 结论 | 归属 |
| --- | --- | --- |
| 属性面板「尺寸」两个空 input 的视觉重量 | **是真问题，且能一句话说清**：底色 `--bg` 比面板 `--panel` 暗 2 级（凹陷）+ 边框 `--line` + placeholder 3.6:1 低于 AA。3 行令牌级改动即可（C4）。不是「感觉轻」，是「凹 + 弱对比」两个具体成因。 | 阶段一 C4 |
| 时间轴刻度尺（10px 字）与段条（12px 高）的信息密度 | 段条 `FPS_H` 是 task-14 刚定过的 12，**不要再动**；刻度尺 `RULER_H 30px` 有余量，把标签 10 → 11px 是安全的（刻度间距 28px，11px 下 `0.1s` 约 22px）。密度问题不在高度，在**字号只有一档**（H1）。 | 阶段二 H1 |
| 状态栏三段信息的层次 | **DOM 只有两段**（`.stb-left` / `.stb-right`），左段内部是 ` · ` 串起来的 5 项，两段同色同字号（C3）；右段还多一个前导 `·`（C2）。「三段」实际是「两段 + 串串」，所以层次问题比想象的更基础。 | 阶段一 C2 / 阶段二 C3 |

## 7. 不做的事（写出来是为了防止被当成遗漏）

| 不做 | 理由 |
| --- | --- |
| 改配色（`#141518` 系） | 深色阶梯已经用了 5 级且都合理，A2 的高光方案比重配色更省 |

| 像素字体 | Aseprite 的做法依赖 200% 缩放，我们的 UI 在 100% 下渲染，换成像素字会糊 |
| 重构布局模型（G2 除外） | 阶段三先出方案，本轮只列问题 |
| 缩小 `FPS_H` 或段条字号 | task-14 已用几何读数（段条 807..819 / 刻度 825..835，间隙 6px）定过，不再翻案 |
