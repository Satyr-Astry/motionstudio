# 本地化（i18n）

**一句话**：界面上的每一句话都住在 `app/i18n/` 里，代码只拿键去查；英文是缺省语言。

这份文档写给要加一句用户可见文案的人。看完你应该能在不读 `app/i18n/index.mjs` 的情况下改对一处，并且知道怎么验证自己没改坏别的。

---

## 1. 三条硬规则

违反任意一条，测试或检查器会拦下来 —— 这不是风格偏好，是这一批（v8 第三十批）踩过硬钉子之后定死的。

**① 源码里不留中文原文。** 迁移后的写法是 `t('board.brush.size')`，**不是** `t('board.brush.size', '笔刷大小')`。

原因很实在：`_check-i18n.mjs` 数的是**源码里的中文字面量**。第二参把中文留在源码里，词条化在条数上就是中性的 ——「还差多少」永远量不出来。缺词风险由三重保障兜住：分片合并时撞键直接抛错、每条键在两表都非空且不等于键名（有测试逐条断言）、`--strict` 缺口 0。

**② 一句话就是一条词条，用占位符，不要拆句再拼。**

```js
// 对：整句成条，语序由译文自己决定
t('shell.export.done', { n: 12, dir: 'C:/out' })   // 'Exported {n} frames to {dir}'

// 错：拆成三段再 + 拼，英文语序会被中文语序绑死
t('shell.export.done.prefix') + n + t('shell.export.done.suffix')
```

**③ 落盘值一个字符都不改。** 词条只管用户**看到**的字。`.msp` 里的字段值、`localStorage` 的键、IPC 通道名、图层的 `kind`、效果的 `type`、参数名、导出 JSON 的键 —— 这些是数据，不是文案。有一批测试专门钉这件事（例如 `tests/i18n-parts-effects.test.mjs` 断言存档里的效果只允许 `type` / `id` / 参数名 / `tracks`）。

> 中文**注释**不用翻译，也不用迁。`_check-i18n.mjs` 会跳过整行注释与字符串外的 `//`。

## 2. 文案住在哪

`app/i18n/` 下是「基础表 + 分片」：

| 文件 | 放什么 |
| --- | --- |
| `index.mjs` | 查表与切换语言的**唯一入口**（`t` / `setLocale` / `normalizeLocale` / `htmlLangOf` / `keysOf` / `has`） |
| `en.mjs`、`zh-Hans.mjs` | 基础表：全局共用的那几十条（应用名、语言自称、偏好项、15 个编辑器的标题与悬停提示） |
| `parts/index.mjs` | **分片注册表**（`PARTS`）。新加一个分片文件必须在这里登记，否则那份词条不会被合并进来 |
| `parts/help.mjs` | 帮助面板（快捷键、概念、图例、曲线提示） |
| `parts/commands.mjs` | 命令面板的命令名与分组 |
| `parts/effects.mjs` | 效果名、效果参数名、效果界面文案、对象种类 |
| `parts/panels.mjs` | 各面板的**单一数据源常量**（`KIND_TEXT`、`LOOP_VALUE`、`STATE_LABELS`、`SECTIONS` 等） |
| `parts/shell.mjs` | 外壳与通知（导出、保存、打开、自动保存、顶栏提示） |
| `parts/board.mjs` | 画板（纹理像素编辑器） |
| `parts/layers.mjs` | 叠放面板与曲线编辑器 |
| `parts/props.mjs` | 属性类面板（变换、纹理、对象属性、偏好、文档、洋葱皮、信息） |
| `parts/timeline.mjs` | 时间轴、关键帧菜单、时间描述 |
| `parts/projects.mjs` | 项目库、导入、导出选项、PSD 解析错误 |

分片是按**代码归属**切的，不是按词条类别。理由：改一个面板只动一个文件，多个面板的本地化可以并行做，不会在一张大表里打架。

**键语法**：`区域.实体.字段`，全小写、点分层，例如 `editor.timeline.title`、`effect.blur.param.amount`、`shell.export.done`。键在**分片之间不许重复** —— 合并时撞键会直接抛 `i18n 词条重复`，因为静默覆盖是最难查的一类 bug。

## 3. 加一条文案：五步

1. 在**对应分片**的 `en` 表与 `'zh-Hans'` 表各加一条，键相同。
2. 在代码里把中文字面量换成 `t('<键>')`，需要变量就用第二参传对象：`t('k', { n })`。
3. 如果这句文案出现在**模块级常量**里（不是函数体），写成访问器：

   ```js
   export const KIND_TEXT = {
       get paint() { return t('layers.kind.paint'); },
   };
   ```

   原因见第 5 节 —— `setLocale()` 只换表，不重建模块常量。
4. 写一条测试断言它（至少断言「两表都有这条键、且取出来的不是键名本身」）。
5. 跑四道门（见第 6 节）。

## 4. 占位符

语法 `{name}`，由 `t(key, vars)` 替换，`vars` 是普通对象。

- **没有对应变量时原样保留**（会看到 `{n}` 挂在界面上）。这是故意的：宁可露出一个显眼的 `{n}`，也不悄悄吞掉调用方写错的变量名 —— 后者会变成「界面上那句话少了数字，但没人报错」。
- 值做 `String()` 转换，数字、字符串都行。
- `t(key, '原文')` 的第二参传**字符串**时，语义不是占位符，而是「这条缺失时的回退文案」。**新代码不要用这个形态**（见硬规则①），它只为「确实是运行时兜底」的少数场景保留。

拼句的正反例，用真实的那个硬骨头说明：

```js
// app/core/timegraph.mjs 的 describeTime()：状态词 + 数值 + 单位 + 缓动 + 吸附
// 对：整句一条，五种语言都能自己排语序
time.describe: '{state} · {value} {unit} · {ease} · {snap}'
// 错：把「·」两侧、单位后缀、「第 N 帧」都拆成独立词条再拼
```

同一句里如果有「前置状态词」这种中文特有的语序（"偏移 +0.30 秒"），英文可能写成 "Offset +0.30 s"，所以整句成条；实在要复用片段，也只复用**名词性**的短词条（如单位名），不要复用虚词。

## 5. 切语言时会发生什么

```
用户在设置里点「English」
   └─ prop-prefs.mjs: ctx.setLocale(val)
        └─ app.mjs: DS.setPrefs({ locale })           // 存进 ms.prefs
        └─ app.mjs: applyLocale(id, { remount: true })
             ├─ i18n.setLocale(id)                    // 只换表，返回 changed
             ├─ document.documentElement.lang = htmlLangOf(id)   // en / zh-CN
             ├─ view-host.remountAll()                // 重挂各面板（跳过画布实例）
             └─ shortcuts.setGroups(overlayGroups())  // 快捷键浮层挂在 body 上，不归 remountAll 管
```

三个设计决定，改动前先读这一段：

**`setLocale()` 只换表、不重绘。** 把重绘写进去会形成 `i18n → view-host → 编辑器 → i18n` 的回环。

**模块级常量必须写成访问器。** `setLocale()` 不会重建已经求值过的模块常量。写成普通属性（`label: '笔刷'`）就会把**首次渲染时的语言**冻在里面，切语言后只有它不变 —— 这是最难发现的一类漏翻。访问器每次读多一次查表，换来所有消费者零改动。

**画布实例跳过重挂。** `remountAll()` 明确跳过 `view.canvasInst`：引擎宿主与视口在里面，重挂会丢掉正在画的那一笔。

启动期顺序也有约束：`boot()` 里 `applyLocale()` 必须在 `buildViews(loadLayout())` **之前**，否则第一帧会先按缺省语言渲染、再被重挂刷掉，肉眼能看见闪一下。

## 6. 进度尺怎么读

```bash
npm run check:i18n          # 只报数，永远 exit 0 —— 这是进度尺，不是闸门
npm run check:i18n:strict   # 结构缺口 > 0 时 exit 1
```

`npm run check` 里接的是非 strict 版。**这是刻意的**：P1–P4 期间中文不可能归零，如果闸门要求「命中即失败」，它从第一天起就一直是红的，等于没有闸门。

输出四段：

1. **进度表**：仍未走词条表的中文，按条数排行（TOP 15），后面跟一句「另有 N 个文件」。
2. **词典**：`en` / `zh-Hans` 各多少条，键集合是否镜面。
3. **语言白名单**：`app/core/prefs.mjs` 与 `app/i18n/index.mjs` 的 `LOCALES` 是否一致（`prefs.mjs` 刻意自己存一份，保持纯函数零依赖）。
4. **编辑器覆盖**：注册表里每个编辑器是否都有 `title` + `hint`。

末行是汇总：`扫描 N 个模块；中文文案 M 条（K 行，F 个文件），词典缺口 0 处，t 遮蔽 S 处`。

还有一段 **`t` 被局部标识符遮蔽**：`t` 只有一两个字母长，很容易被 `const t = e.target` 或 `const t = TOOLS.find(...)` 抢占 —— 那之后在同一个作用域里调 `t('…')` 会把 DOM 节点或数组项当函数调，运行时才炸。检查器只在**真的 import 了 `t` 的文件**里、且只在取值来源像对象（DOM/查表/`find`）时报出来，是个位数级别的自查清单，不是零容忍的闸门。看到自己的文件在里面，就去看那个作用域里有没有调 `t()`；有就改名（`target` / `tgt` / `el`），没有也可以顺手改掉，省下一个人猜。

`--strict` 只在**结构**问题上失败（镜面不平、编辑器缺覆盖、白名单不一致），**不因条数或遮蔽失败** —— 条数是进度，不是错误。

## 7. 改文案时容易踩的三件事

**测试按中文匹配。** `tests/psd.test.mjs`、`tests/timegraph.test.mjs`、`tests/shortcuts-overlay.test.mjs`、`tests/drag-tip.test.mjs` 等按中文片段或整句断言。改文案要同步改断言，并且**把期望值改成从词条取**，不要图省事换成 `assert.ok(err)` 那种「怎么都过」的写法 —— 那会把真 bug 一起盖住。

**宽度会变。** 英文普遍比中文长。三处已知紧的地方：`panels.css` 的 `.tline-bar` 标签（1280 宽下宽裕度很小）、`.lyr-sub`（宽度预算约 134px）、`button.prop-seg`（`flex: 0 0 auto` 且**没有省略号兜底**）。加长文案后要在真机上看一眼，不要只跑测试。

**颜色与数字格式没做。** 日期、数字、百分比的本地化格式当前统一用浏览器的默认表现；`Intl` 没接。这不影响界面文案，但如果你要加「2026 年 11 月 2 日」这种，请先看有没有现成的格式化工具，没有就保持 ISO 形态，别手拼。

## 8. 不做什么

- **不做 RTL。** 界面用 `flex` 与固定像素定位混排，镜像布局是另一件事，不在本地化范围内。
- **不做构建期替换。** 本项目的铁律是「无构建步骤」（见 `README.md` 的 Design principles）：开发时读到的源码必须就是用户看到的那份。构建期替换会让 `_check-static.mjs` 扫不到译文，也让「开发环境一份、用户看到另一份」的差异无法自证。
- **不共用主进程的词条表。** `main.js` / `preload.js` 是 CJS，渲染进程是 ESM，且主进程只有 24 条对话框与错误串。两边各自维护，靠 `tests/ipc-contract.test.mjs` 守住通道名这条硬契约（通道名不是文案，不许本地化）。
- **不翻译日志与代码注释。** 报错栈、`console.warn` 里的诊断信息、注释保持中文 —— 它们是写给维护者的，不是写给用户的。
- **不翻译 API 的诊断返回值。** 例如 `app/core/timegraph.mjs` 里 `{ ok: false, reason: '…' }` 那类：`reason` 是程序内部与测试用的分类标签，不是界面上的一句话。要展示给用户时，由调用点根据自己的场景取一条**界面词条**，不要把诊断串直接甩到界面上 —— 那既难翻译，也把内部实现细节漏给了用户。
