## 1. 点对象后浮动工具条里的「＋效果」点了没反应

**现象**：画布对象左上角的浮动条上点「＋效果」，菜单能弹出五个效果，点任意一项，对象上什么都没发生，属性面板也不出现「效果」组。

**根因**：`app/editors/canvas-chrome.mjs` 的 `currentEl()` 用 `Array.isArray(d.layers)` 当守卫。v6 起文档容器是 `doc.objects`，`d.layers` 恒为 `undefined` → `currentEl()` 恒返回 `null` → 菜单项的 `if (!el2) return` 把动作静默丢掉（连异常都没有，所以 `__errs` 一直是空的）。

**修复**：`currentEl()` 改成 `objectsOf(d).find((l) => l.id === s.id)`（`objectsOf` 兼容 `objects`/`layers` 两种容器）。

**证据**：真机点第一项（模糊）后 `effects.length` 0 → 1、`.fx-list` 出现 1 行「模糊 × 模糊半径 4 ◆」、浮动条文案变「效果 1」。

## 2. 浮动工具条里的「网格」点了没反应

**现象**：点「网格」后画布上既不出现网格线，也拖不动任何顶点。

**根因**（两条叠加）：
1. 点「网格」只调 `ctx.setSelection({ mode: 'warp' })`，但对象身上没有 warp 时 `elementLattice` 回退 `createLattice(1, 1)` —— 1×1 网格没有内部线、没有内部顶点，画面上等于没变化。
2. `app/editors/canvas-input.mjs` 的 `setSelectionActive()` 每次指针按下都无条件 `setSelection({ mode: active ? 'transform' : null })`，把手动切到的 `warp` 模式冲掉；拖动顶点时更是只剩一个 `vertex`，`mode` 已经变回 `transform`。

**修复**：
- `canvas-chrome.mjs` 新增 `ensureWarpGrid()`：`latticeOf(id)` 的 cols/rows 都 < 2 时先 `ctx.setLatticeDiv(2, 2, id)`（`ctx-time.mjs:263` 的 `keep` 保证这步不会被当成空 warp 丢掉，并 flash「网格 2×2」），然后才 `setMode('warp')`。
- `canvas-input.mjs` 的 `setSelectionActive` 加 `keepMode` 参数：拖动顶点时传 `true`，从当前 `ctx.selection().mode` 读回模式，不再硬写 `transform`。

**证据**：真机点「网格」后 `latticeOf` = `{cols: 2, rows: 2}`、`selection()` = `{id, mode: 'warp', vertex: null}`、hint 显示「网格 2×2」；拖中心顶点 `selection().vertex === 4`，松手后文档里 `warp.pts[4] = [69.57, 44.27]`（55×35 CSS px @ zoom 0.79，比例正确）。

## 3. 选中对象后「加画格」像失败

**现象**：在时间轴工具条点「加画格」，或在对象面板的画格栈点「＋」，多数时候什么都没发生；偶尔成功一次，之后再点就没反应。

**根因**：`app/shell/app.mjs` 的 `addCelAt(objId, t)` 直接 `ensureCelAt(obj, t, { inherit: true })`。`ensureCelAt` 的语义是「这个时刻已经有画格就用它」——播放头正停在已有画格上时它返回同一格，于是「加了一格但看不见」，也没有任何提示。用户第二次点仍然落在同一时刻，永远不会有新格子。

**修复**：新增 `findFreeCelTime(obj, t)`，从当前时刻按 `1/fps` 往后找第一个没有画格的帧边界（最多找 240 帧防死循环）；`addCelAt` 改用这个落点，并在顺延时 `flash('该时刻已有画格，已放到 X.XX s')`。返回值改成真正的落点时刻，时间轴与画格栈的选中/滚动都以它为准。

**证据**：真机对象只有 `at=0` 一格、播放头在 0 时点「加画格」→ `celTimesOf` 从 `[0]` 变 `[0, 0.0833]`（12fps），hint =「该时刻已有画格，已放到 0.08 s」。

## 4. 不能自定义对象尺寸

**现象**：属性面板的「尺寸」是只读文本，只能看不能改；导入的 PSD 图层、画笔对象都只能用文档画布那一档分辨率。

**修复**：
- `app/core/doc-model.mjs` 新增 `setObjectSize(doc, id, w, h, { makeCanvas })`：把该对象**所有画格**的位图整张拉伸到新尺寸（等同 Photoshop 的「图像大小」，视觉不变、只改分辨率）；同尺寸直接原样返回；上限 4096。
- `app/shell/app.mjs` 的 ctx 新增 `setObjectSize(objId, w, h)`（走 `setDoc`，进撤销栈）。
- `app/editors/prop-kit.mjs` 新增 `makeNumPair(body, labelText, opts)`；`app/editors/prop-object.mjs` 把尺寸行换成两个数字框（1..4096，`coalesce: 'obj-size:' + id`，无位图时 `disabled` 并显示「—」）。

**证据**：真机宽 400 → 300，对象变 300×300，所有画格同步；高 → 301 得 300×301；一次 `undo()` 回到 400×300（两次改动落在同一合并窗口 = 一步撤销）；输入 99999 夹到 4096、0 夹到 1；无位图时两个框 `disabled` 且显示「—」。

## 5. 网格变形只能线性，选「贝塞尔」没效果

**现象**：把网格顶点拖出关键帧、并把缓动切成贝塞尔后，对象的位移/缩放会按曲线走（有预冲、过冲），但网格变形仍是匀速，甚至像被削平。

**根因**：`app/core/lattice.mjs` 的 `lerpLattice` 里 `const u = clamp(num(t, 0), 0, 1)`。传进来的 `t` 已经是「缓动后的进度 p」，贝塞尔预冲会 < 0、过冲会 > 1，clamp 把它们全部夹回端点 → 网格冻在第一帧或直接跳到末帧，看起来就像「只有线性」。

**修复**：
- `lattice.mjs`：去掉 clamp（`const u = num(t, 0)`），非有限值仍回落 0；注释写明这是缓动后的进度，必须允许外插。
- `app/core/transform.mjs`：抽出 `segmentProgress(key, u)` 作为**唯一**缓动来源，`baseStateAt` 与 `channelValueAt` 都改用它（hold 的短路仍在取 p 之前，整段保持的语义不变）。
- 新增 `tests/warp-ease.test.mjs` 10 例。

**证据**：span=2s、`h1=[0.42,0]`/`h2=[0.58,1]` 时，`t=0.25` 的 warpX = **12.916**（线性会是 25），`t=0.75` = **87.084**（线性 75），`t=0.5` = 50（对称曲线中点必然相等）。预冲曲线 `h1=[0.34,-0.3]` 在 `t=0.1` 得 warp = **-3.396**（修复前恒 0）；过冲 `h1=[0.34,1.56]` 在 `t=1` 得 **108.74**（修复前恒 100）。

## 6. 网格变形不会在动画里微分呈现

**现象**：把网格拖变形并打上关键帧后播放，画面只在关键帧处「跳」，中间过程看不出渐变；或者干脆整段都不变形。

**根因**（三条叠加）：
1. 1×1 网格没有可拖的顶点（见第 2 条），用户实际上没真正写下 warp 数据。
2. `lattice` 拖动写键用的是「当前时刻」，但对象如果只有 1 个关键帧且播放头不在 0，就会得到「首帧在 0.37s、之前什么都没有」的形态，播放时前半段看起来完全不动。
3. 第 5 条的 clamp 会把中间进度削平。

**修复**：`app/shell/app.mjs` 新增 `ensureWarpBaseKey(objId)`：网格拖动开始时，若该对象关键帧少于 2 个且当前时刻 > 1e-6，先在 0 秒补一个基准关键帧（值取当前状态），让这次变形成为一段真正的动画；配合第 2 条的 `ensureWarpGrid()` 与第 5 条的缓动修复。

**证据**：真机写两帧（0s 网格偏移 0、1s 偏移 40）后逐帧合成取内容包围盒：`t=0` → x0=0，`t=0.5` → x0=**20**，`t=1` → x0=**40**，中间帧确实在微分。

## 7. 网格变形后对象上有极细的三角形缝隙

**现象**：网格变形后放大看，对象内部出现 1px 的浅色/透明细线，网格越密越明显。

**根因**：`app/paint/composite.mjs` 的 `drawTexCell` 把每个格子切成两片三角形，先用 `ctx.clip()` 再贴图。抗锯齿让两片三角形共享边两侧各损失约半个像素的覆盖率，`source-over` 叠加后 `alpha = 1 - (1-0.5)² = 0.75` → 正好是 191/255 的浅线。

**修复**：
- 新增导出 `inflateTriangle(pts, pad)`：按有向面积算每条边的外法线、外移 `pad` 后再斜接（`MITER_LIMIT = 6`，零长边/共线/尖角退化时沿角平分线推 `pad`，绝不产生 NaN；不改入参）。
- 新增导出 `devicePad(g, px)`：用当前变换矩阵取 `min(sx, sy)` 把「0.5 设备像素」换算成用户单位（上限 1024）。
- `drawTexCell` 用外扩后的三角形做 `clip`，贴图用的 `triAffine` 仍用原始四边形（纹理映射不变）。

**证据**：页面内离屏 A/B，同一不透明纹理 + 2×2 网格 seg=6，统计「距轮廓 ≥ 4px 的内部像素」中 `alpha < 250` 的数量：旧实现 **6769 / 36864**（`minAlpha = 191`，正是 0.75×255），新实现 **0 / 37503**；DPR=2 下同样 0 / 148730。截图 `E:\dev\ms-harness\shots\warp-seam.png`。

**补充（性能优化后）**：平行四边形子格现在走仿射快路径，一次 drawImage 铺满、根本没有共享边，缝隙问题在这类格子上从根上消失；只有真正非仿射的子格才用「外扩 + 两片三角形」。

**已知取舍**：对称外扩保证「任何像素至少被一片完整覆盖」，代价是图层不透明度 < 75% 时这条共享边从「偏暗 0.25a」变成「偏亮 a(1−a)」（a=0.5 时 127→191）。要同时消灭半透明层的这条线，需要「整层先画进离屏再整体上 alpha」，属于绘制管线改动，本轮没做。

## 8. 渲染与处理较慢、操作有延迟感

**先量再改**（真机 `performance.now()`，3 个 400×300 对象、900×640 画布）：

| 场景 | 改前 | 改后 |
|---|---|---|
| 无变形合成一帧 | 0.05 ms | 0.07 ms |
| **有网格变形的合成一帧** | **7.42 ms** | **1.09 ms** |
| `engine.render()` | 1.77 ms | 0.1 ms |
| `setTimeClamped()`（含面板刷新） | 0.03 ms | 0.03 ms |

结论：慢的不是「每帧合成」本身，而是**网格贴图**。`drawLatticeImage` 原来对每个 cell 一律切 6×6 子格、每子格两片三角形、每片一次 `clip()`；一个 2×2 网格的对象一帧就是 4×36×2 = **288 次 clip**，clip 是这条管线里最贵的调用。

**两处优化**（`app/paint/composite.mjs`）：
1. **仿射快路径** `isAffineQuad(D, eps)`：子格四角若构成平行四边形（纯仿射，没有透视/非线性），就不必切三角形——一次 `setTransform + drawImage` 精确铺满，**零 clip、零共享边**。旋转/缩放/平移出来的格子全走这条路。
2. **自适应细分**：`n` 由格子实际像素大小决定（≤64px → 1 段，≤200px → 2 段，更大 → 3 段），并把 `devicePad()` 从「每片算一次」提到「每次绘制算一次」。

**质量验证**：200×150 纹理、强变形网格下，`n=2` 与 `n=6` 的整幅像素差 **0 像素**（最大 alpha 差 0）。缝隙复检：300×200 纹理 + 2×2 乱拖网格，内部像素 61714 个里 alpha<250 的 **0 个**（`minAlpha = 255`）。

**还留在桌上的**：静态 warp（不参与动画）本可以缓存成离屏位图，编辑时每帧重算还没做；`engine.render()` 里的 gizmo 每帧全量重绘也没做增量。
