# 导出栈现状与本批改动（2026-10，第 32 批）

> ## ⚠️ 动采样之前先读这一段
>
> **仓库里有两个同名但语义完全不同的 `sampleTimes`：**
>
> | 位置 | 第二参的含义 |
> | --- | --- |
> | `app/core/timebase.mjs:146` | **结束时刻**（秒）。内部按每段的 `fps` 步进，条件是 `segStart < end - 1e-9`。**导出链路用的是这个。** |
> | `app/core/doc-model.mjs:889` | **步长**（秒）。 |
>
> 拿后者去验「这次导出了几帧」会得出完全错误的结论 —— 我本人因此一度得出
> 「现有导出一律只导 1 帧」的假结论并写进了报告。判断依据只有一个：**看 import 来源**，
> 不是看函数名，也不是看第二个实参长什么样。

> 目的：把「导出」这条链从 UI 到落盘写清楚 —— 三条通道各自的数据从哪来、经过谁、
> 最后写到哪、谁消费。第 33 批（分张 / trim / Phaser）与第 34 批（WebCodecs）
> 照这份往下接，不需要重新考古。

## 1. 三条通道的现状

| 通道 | 入口 | 采样 | 落盘 | 主进程 |
| --- | --- | --- | --- | --- |
| PNG 序列 | `projectApi.exportFrames()` | `core/timebase.mjs` 的 `sampleTimes(doc, endSeconds)`：按每段的 `fps` 生成时刻 | 主进程逐帧写 `frame_0001.png`… | `main.js` 的 `ms:export-frames` |
| 精灵图 | `projectApi.exportSpritesheet(opts)` | `shell/spritesheet.mjs` 的 `buildSpritesheet(doc, opts)` | `<名字>-sheet-<stamp>/` 下的 `<名字>.png` + `<名字>.json` | `main.js` 的 `ms:export-sheet` |
| WebM | `projectApi.recordVideo(opts)` / `exportVideo(opts)` | 墙上时钟：`captureStream(0)` 手动推帧，每帧 `await` 一个 `1000/fps` | 不落盘（返回 `ArrayBuffer`，由上层决定去处） | 无 |

**采样函数有两个同名不同义的版本，改之前先看 import 来源**：

- `app/core/timebase.mjs:146` 的 `sampleTimes(doc, total)` —— 第二参是**结束时刻**，
  内部按段的 `fps` 步进、`segStart < end - 1e-9`。**导出链路用的是这个**。
- `app/core/doc-model.mjs:889` 的 `sampleTimes(doc, step)` —— 第二参是**步长**。
  拿它去验「导了几帧」会得出完全错误的结论（我踩过一次，以为现有一律只导 1 帧）。

## 2. 本批改动

### 2.1 新增纯逻辑 `app/core/export-options.mjs`

零 DOM、可在 node 直跑，全部是「输入 → 输出」：

- `normalizeExportOptions(raw, doc)` → `{scale, fps, from, to, background, bgColor, openAfter, dir, width, height, total, count}`。
  **坏值回落默认，不夹到边界**（`scale: 'abc'` 得到 1，不是 0.05 —— 夹到边界会造出一个用户没要过的极端值）。
- `frameCount({from, to, fps})` = `Math.ceil(span * fps - 1e-9)`，**左闭右开**。
- `sampleTimesFor({from, to, fps})`：长度恒等于 `frameCount`，时刻保留 6 位小数。
- `uniqueDirName(base, exists)`、`chunkPlan(count, size)`、`EXPORT_CHUNK = 16`。

### 2.2 帧数语义：左闭右开

与 `timebase.sampleTimes` 的半开区间一致，否则同一个工程导出帧数会变，老用户对不上。

| 范围 | fps | 帧数 |
| --- | --- | --- |
| `0 – 1s` | 12 | 12 |
| `0.5 – 2.0s` | 24 | 36 |
| `0 – 0.04s` | 24 | 1（最短非空） |
| `out <= in` | 任意 | 0，提示「时间范围为空」 |

这四组钉在 `tests/export-options.test.mjs` 里。

### 2.3 PNG 序列改成「分片落盘」

原先一次把整段帧数组推进 IPC（4K×200 帧就是 200 个 dataURL 一次性跨进程）。
现在每 16 帧一片：`ipc.exportFrames(name, frames, {dir, startIndex, total})`。
主进程按 `startIndex` 续写 `frame_%04d.png`，**首片建目录并做重名去重**，把最终目录名回传，
后续片沿用。取消 = 少发后几片，**已写出的片留在磁盘上**。

每片之间 `await` 一次宏任务 —— 否则整段在一个任务里跑完，进度条一帧都不动、取消按钮也点不到。

### 2.4 目录去重（覆盖保护）

`stamp()` 只到秒。同一秒里连点两次导出会落进同一个目录，第二次 `writeFileSync` 静默覆盖第一次。
`main.js` 新增 `uniqueDir(base)`：被占用就试 `-2`、`-3`…，999 次都撞上则返回空串、由调用方报错。

**不传 `dir` 时路径逐字不变**：`图片/MotionStudio/<sanitize(name)>-<stamp()>/frame_0001.png`。
这条是硬验收 —— 同一份工程改前改后目录内容必须一致。

### 2.5 导出对话框 `app/editors/export-dialog.mjs`

一个浮层收全部参数，三条通道共用。键盘契约（真机验过，见 §3）：

- `Esc` 关闭且**不导出**；
- `Tab` 能走完所有控件（10 个可聚焦元素、0 个 `tabindex=-1`）；
- `Enter` 等于点「导出」（输入框里同样成立，`select` 除外）；
- 打开时焦点落在「导出」按钮上。

参数记忆在 `localStorage['ms.export']`，只存白名单字段；坏 JSON / 越界值回落默认。

样式：进度条在 `app/styles/export.css`（`.exp-progress`，单独一条 `[hidden]` 兜底），
其余内联在模块里 —— 避免与面板样式互撞。

### 2.6 双语义：旧调用零变化

```js
exportFrames('工程名')   // 旧调用 → exportFramesLegacy，整段一次导，不弹框
exportFrames()           // 新调用 → 弹对话框
exportFrames({__direct}) // 内部/测试 → 直接走分片
```

`app/shell/project-io.mjs:1293` 那一处 `exportFrames(projectLabel())` 因此逐字保持老行为。

### 2.7 WebM 接上时间范围与进度

`recordVideo(opts)` 现在认 `opts.from`（起点秒）与 `opts.onProgress(done, total)`：
`compositeFrame` 的时刻从 `from + i/fps` 算，进度回调每帧发一次。
对话框把 `seconds` 传成 `out - in`。

## 4. 留给第 33 / 34 批的接口位

写清「数据从哪来、写到哪、谁消费」，不是 TODO 占位。

### 4.1 分张导出（第 33 批）

- **数据从哪来**：每个对象的每一帧图像 —— `core/doc-model.mjs` 的 `imageAt(obj, t)`，
  或按纹理取 `drawingsOf(obj)` 的 `rec.image`。
- **写到哪**：与 PNG 序列同构的目录，每张一个子目录或文件名加对象标识；
  复用 `main.js` 的 `uniqueDir` 与 `frame_%04d` 命名规则，别另写一套。
- **谁消费**：用户手工切图，或第 33 批的 Phaser 打包器（读目录清单）。
- **接口位**：`normalizeExportOptions` 加 `split: boolean` / `splitBy: 'object'|'texture'`；
  `chunkPlan` 不变（分片按帧数，与分张正交互）。

### 4.2 trim（第 33 批）

- **数据从哪来**：`app/paint/trim.mjs` 的 `contentBounds(rgba, w, h)` —— 已存在，纯函数。
- **写到哪**：导出前对每帧做一次 `cropRgba`，或只报告「内容包围盒」让用户自己决定。
- **谁消费**：精灵图的 `json` 里原本就有每帧 rect，trim 之后要同步改它，
  否则消费方（Phaser / Pixi）按旧 rect 截会切到空白。
- **接口位**：`normalizeExportOptions` 加 `trim: boolean`；`buildSpritesheet(doc, opts)` 已收 `opts`，
  直接透传即可。

### 4.3 WebCodecs（第 34 批）

- **数据从哪来**：与 `recordVideo` 相同 —— `compositeFrame(cv, doc, t, {clear:true})` 逐帧画到离屏 canvas。
- **写到哪**：`VideoEncoder` → `EncodedVideoChunk` → `mp4/webm` 封装器（需要新依赖，或手写最小封装）。
- **谁消费**：用户下载；若做透明通道，`VideoFrame` 支持 alpha，但容器要能承载（VP9 alpha 的 WebM 可以）。
- **接口位**：`recordVideo(opts)` 加 `opts.codec: 'mediaRecorder'|'webcodecs'`，
  两条路都返回 `{ok, bytes, size, mime, frames, fps, seconds}`，
  这样上层（`exportVideo` → 另存）完全不用改。

## 5. 本批没做的

- **真机落盘验收**：浏览器无 IPC 桥，跑不了。「老路径目录一致」「`dir` 自定义生效」
  要在 Electron 里验（Lead 汇总时做）。
- **进度条动画**：分片之间让出了宏任务，进度会跳 16 帧一格，没有做平滑插值 ——
  真实导出速度下这个粒度够用，插值反而会让「卡住」看起来像「还在跑」。
- **导出队列**：多通道同时导出会互相覆盖进度条，现在靠 `busy` 标记串行化，没做队列 UI。

# 第 33 批（已落地）：导出通道补齐

> 上一批把「导到哪、导几帧、怎么问」补齐了，这一批补的是**产物本身的形状**：
> 图集太大撞引擎上限、帧里大量透明边、JSON 喂不进 Phaser、只能整段导。

## 6. 分张：撞上限就切成 sheet-1…N

- **纯函数** `splitSheetLayout(layout, maxTextureSize)`（`app/shell/spritesheet.mjs`）：
  输入单张布局，输出 `{ok, reason, sheets:[{file:'sheet-1.png', width, height, columns, rows, frames}]}`。
- **切法**：每张最多 `floor(max/格宽) × floor(max/格高)` 格，帧按全局 `index` 顺序连续切，
  每张自己重排 `x/y`（格位），`index` 保留全局值 —— 消费方按 `index` 对动画帧，不看它在哪张。
- **单帧本身就超上限**时**明确报错**、不产出任何图：
  `单帧 5000px 超过图集上限 4096px，请调大上限或缩小缩放`。
  静默产出一张超限的图，等于把失败推迟到引擎加载那一刻，更难查。
- **`meta.sheets[]`** 与磁盘文件一一对应（`{file, width, height}`），消费者按它逐张加载。
- 上限来源：`normalizeExportOptions` 的 `maxTextureSize`，夹 `512..8192`，默认 4096。

## 7. trim：内容盒 + **格尺寸跟着缩**

两件事分开做，缺一件都不省体积：

1. **帧表加内容矩形**：`sx/sy/sw/sh`（内容相对**原始帧左上角**）+ `trimmed`。
   `x/y/w/h` 是格位，**永远不动** —— 消费方的「格位 + 源矩形」才拼得出正确画面。
   全透明格与「内容占满整格」都退回整格并标 `trimmed:false`（否则消费方拿到 0×0 帧）。
2. **格尺寸收缩到「所有帧内容盒的最大宽高」**：`cellW = max(sw)`、`cellH = max(sh)`，
   再用 `sheetLayout(doc, {…, cellWidth, cellHeight})` 重排。

第 2 条是第一版漏掉的，真机抓的：只做第 1 条时图集仍是 `2700×640`、字节数
`35589 vs 35598`（几乎没变，只是把内容挪到了格左上角）。补上第 2 条后：

| | 图集尺寸 | 单张 PNG |
|---|---|---|
| trim 关 | 2700×640 | 13815 B |
| trim 开 | **420×84** | **868 B（−93.7%）** |

复用 `app/shell/import-file.mjs` 的 `alphaBounds` 找盒子（导入链路同一条扫描），但是
**`trimCellBox` 自己按 `>=8` 判不透明**：命中的 `hitTest` 用的是 `alpha > 8`（严格大于），
两者故意不同 —— 命中要「宁可选中」、裁边要「宁可多留一行像素」。

## 8. 引擎格式：先只做 Phaser 3 的 JSON Hash

`phaserJSON(sheet, {image})` 输出严格的 JSON Hash（`frames` 是对象、不是数组）：

| Phaser 字段 | 来自 |
|---|---|
| `frames['frame_0000'].frame` | `{x: 格位x + sx, y: 格位y + sy, w: sw, h: sh}` |
| `.trimmed` | 该格 `trimmed` |
| `.spriteSourceSize` | `{x: sx, y: sy, w: sw, h: sh}` |
| `.sourceSize` | `{w: cellWidth, h: cellHeight}`（**收缩后的格**，不是文档尺寸） |
| `.rotated` | 恒 `false`（不做图集旋转打包） |
| `meta.image` / `meta.size` / `meta.sheets` | 文件 / 尺寸 / 分张清单 |

**Godot / Unity 这一轮不做**，理由写在这而不是留 TODO：Godot 的 `AtlasTexture` 要逐帧手写资源、
Unity 要 `.meta` 与 sprite 导入设置，两者都不是「多一个 JSON 字段」能解决的，属于**新通道**
而不是**本通道的一个选项**。真要做，按 §10 的接口位另起。

## 9. 单帧与剪贴板

- `projectApi.exportCurrentFrame(opts)`：`compositeFrame` → `toDataURL` → `ipc.saveBinary` 落盘。
- `projectApi.copyFrameToClipboard(opts)`：`ClipboardItem` + `navigator.clipboard.write`，
  **3 秒超时**（`Promise.race`），失败三条降级各自不同文案：
  - 没有 `ClipboardItem` → 「浏览器不支持写剪贴板」
  - `write` 抛 `NotAllowedError`（常见于窗口没有焦点）→ 「窗口没有焦点」
  - 3 秒没 resolve → 「剪贴板写入超时」
  三条都**自动改走「导出当前帧到文件」**，并在导出之后再 flash 一次结论。
- **踩到的坑**：`fallback` 原本先 `flash(msg)` 再调 `exportCurrentFrame`，而后者失败时会
  `flash('已取消')` **把这句盖掉** —— 真机三次读数全是「已取消」，用户根本不知道原因。
  改成「调完再 flash」（`msg + '，已改为导出文件'` / `msg + '；导成文件也没成功'`）。

## 10. 编码与质量

`format: 'png' | 'webp' | 'jpeg'` + `quality`（`0.1..1`，只对 webp/jpeg 有效）。
**JPEG 不支持透明**：选了 JPEG 会强制用 `bgColor` 铺底并 flash「JPEG 不支持透明，已用 #000000 填底」，
不静默产出一张黑底图。分张时每张按同一个 `format` 编码、扩展名跟着 mime 走。

## 11. 真机读数

**分张几何**（浏览器副本 8900 + CDP 9334，1680×1000，6 帧 × 900×640 格）：

| `maxTextureSize` | 结果 |
|---|---|
| 1000 | 6 张，每张 900×640，1 格/张 |
| 2000 | 1 张 1800×1920（2 列 × 3 行） |
| 5400 / 99999 | 1 张 5400×640（不超限，原样） |
| 128 | 报错「单帧 900px 超过图集上限 128px，请调大上限或缩小缩放」 |

**落盘**（Electron 隔离实例，`--user-data-dir=E:\dev\ms-etmp33`、CDP 9336，跑完已杀、目录已删）：

| 场景 | 目录内容 |
|---|---|
| 分张（`trim:false`, max 1000） | `sheet-1.png` 13815 B + `sheet-2.png` 13815 B + `t33.json` 503 B + `t33.phaser.json` 387 B |
| trim 开、2 帧 | `sheet-1.png` **868 B** + `t33.json` 452 B + `t33.phaser.json` 553 B |

**剪贴板三条**（浏览器副本，无 IPC 桥所以走 fallback）：
`浏览器不支持写剪贴板；导成文件也没成功` / `窗口没有焦点；导成文件也没成功` /
`剪贴板写入超时；导成文件也没成功`（实测 3034 ms）。
