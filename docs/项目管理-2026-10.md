# 项目管理与主界面交互：问题清单与合并计划（2026-10）

> 范围：项目库（`app/editors/projects.mjs` + `app/shell/project-io.mjs`）、存储层（`app/shell/project-store.mjs`）、顶栏项目区（`app/shell/chrome.mjs`）、自动保存（`app/editors/prop-prefs.mjs` 计时 + `project-io.autoSaveProject`）、启动恢复（`restoreLastProject`）。
> 取证方式：读代码钉行号 + 8900 只读副本上跑脚本化真机流程（探针 `ms-view/probe-proj*.txt`，截图 `ms-view/shots/proj-audit*.png`）。所有读数都在下文标「真机」。

## 0. 一句话结论

项目库能存、能读、能改名，但**它把「文件管理器」的心智套在了「文档状态机」上**：任何一次「载入 / 新建 / 删除」都直接换掉或丢掉内存里的文档，而**没有一个地方承认「当前文档有未保存的改动」这件事**。真机上我做了一次可复现的丢数据：改一处属性 → 顶栏显示「项目A •」→ 在库里点「载入」→ 改动消失、`•` 消失、全程没有任何对话框。

## 2. 问题清单

### P1 —— 会丢东西

| # | 现象 | 根因 | 真机证据 |
| --- | --- | --- | --- |
| 1 | **有未保存改动时点「载入」= 静默丢改动** | `loadProject` → `applyDoc(doc, meta)` 全量替换，`applyDoc` 里 `project.dirty = !!m.dirty`；没有任何 `dirty` 前置检查 | 改对象名 → 顶栏「项目A •」→ 点该卡「载入」→ 对象名回到「对象 1」、`•` 消失、`anyDialog:false`、`modalOpen:false`（`probe-proj4`） |

## 3. 修复方案（按依赖排序）

### 第 1 批：不许再丢（数据安全层，`project-io.mjs` + `doc-state.mjs` + 新纯函数模块）

1. **新增 `app/core/project-guard.mjs`（纯函数）**：`guardDecision(state)` → `{action:'proceed' | 'save-then-proceed' | 'ask', reason}`；判据：`dirty === false` → proceed；`dirty && id && name` → save-then-proceed（静默入库，因为保存过就不该再打断）；`dirty && !name` → ask。三处调用点：`loadProject` / `newProject` / `importProjectFile`。
2. **`ask` 分支用三选浮层**（保存并继续 / 丢弃改动 / 取消）—— 复用 `askProjectName` 那套 DOM 写法，但抽成通用 `askChoice`。
3. **删除项目改「确认 + 8 秒撤销」**：`remove` 前弹确认（文案带项目名与「若是当前项目，文档仍在内存」），删除后把整条记录暂存在内存 8 秒并在浮层底部给「撤销删除」按钮；撤销 = `putProject(rec)` 回写。
4. **删除当前项目后**：`project.name = ''`、顶栏回到「未命名项目」、flash 说明「已从库中删除；当前文档还在内存，Ctrl+S 可重新入库」。
5. **`beforeunload` 保护**：只在 `dirty` 时阻止（有名字的先自动保存再放行，未命名的必须问）。
6. **未命名项目的草稿恢复**：自动保存分支改为「未命名 → 写单条草稿 `ms.draft`（IndexedDB 键 `__draft__`），启动时若存在草稿则提示恢复」。这一条让「崩溃即丢」变成「崩溃可恢复」。
7. **首次保存不再弹文件对话框**：去掉 `writeProjectFile(id,{quiet:true})`，文件另存只走显式「存为文件」。
8. **重命名不置脏**：`rename` 里去掉 `dirty = true`（名字不是内容）。

#### 实施记录（第 1 批，W16 · 2026-10-25）

八条全部落地。与上文的偏离只有三处，都记在这里：

1. **撤销条的位置**：浮层开着就贴浮层底部；**浮层没开时用 `position:fixed; left:50%; bottom:18px; transform:translateX(-50%)`**。原因不是审美 —— 实测挂到 `shell.host` 走静态流会落到 `y:43`，被顶栏盖住（`elementFromPoint` 命中的不是撤销条，点「撤销删除」点不到）。改后 `{x:648, y:752, hitInBar:true, hitTag:"BUTTON", barPos:"fixed"}`。
2. **`beforeunload` 与草稿恢复的挂载点**：`installProjectSafety()` 与 `restoreDraft()` 都由 `project-io.mjs` 导出、在 `app.mjs` 的 `boot()` 末尾调用。理由：判断「脏没脏」「有没有名字」要读 `project`（project-io 的模块级状态），放在 `app.mjs` 会逼 project-io 再导出更多内部量；而挂载时机仍由启动钩子控制，避免「import 即副作用」。恢复顺序是 `restoreLastProject()` 成功就不碰草稿（两者同时恢复会互相覆盖）。
3. **顶栏「上次保存 · 存储介质」**：`savedAt` / `storeKind` 由 `currentProject()` 提供，但**不能只加在 `buildCtx()` 上** —— `chrome.mjs` 读的 `api` 是 `app.mjs` 里 `buildTopbar(dom.top, {...})` 那个独立对象，第一次加在 `buildCtx()` 时页面里 `ms.projectSavedAt` 是函数、顶栏却拿不到。两处都补上才通。

真机读数（1680×1000 / 1280×800，8900 + CDP 9334）：

- 脏 + 已命名 → 载入：`settled:true, savedAtNewer:true, askShown:0, dirty:false`（静默入库，无对话框、无三选）
- 脏 + 未命名 → 载入：三选 `["保存并继续","丢弃改动","取消"]`，`hitEl.inAsk:true`，`zAsk:"9999"`；取消后 `docName` 不变、`dirty:true`
- 删除 → 确认 `["删除","取消"]` → 4 张卡变 3 张 → 撤销条出现 → 点「撤销删除」→ 4 张卡复原、`savedAt` 不变
- `beforeunload`：脏时 `prevented:true`、`stillDirty:true`
- 草稿：未命名改动后 `autoSaveProject()` 写 `__draft__`（`isDraft:true`，且**不出现在项目列表里**）；新页面启动弹「发现上次未保存的草稿（21:16），要恢复吗？」，点「恢复」→ 对象名一字不差、`dirty:true`、草稿记录已删
- 重命名：`dirtyBefore:false → dirtyAfter:false`
- 真实点击链（浮层「新建项目」按钮，不绕 API）：三选正常弹出，取消后文档与脏标记都不变，`__msErrors` 长度 0
- 顶栏：`title` = `当前项目：T1 · 上次保存 21:15:34 · 存储：indexeddb`；`indexedDB` 被 stub 掉后 `storageKind()` 与 `current().storeKind` 同时变 `memory`

两条记下来但**本轮没改**的：

- `autoSave` 偏好（设置面板里那档 0/30/60/300 秒）**没有定时器驱动**，全仓只有 `importFileObjects` 之后调了一次 `autoSaveProject()`。所以「自动保存」目前只在导入后与关窗时发生。这属于第 2 批的接线问题，不在本轮。
- `node --test` 与 `_check-static.mjs` 都**发现不了 `project-io.mjs` 的语法错**（测试不 import 它、静态检查只验 import 路径存在性）：本轮就因为重复 `export` 让页面白屏过。以后改这个文件，交付前必须真机开一次。

### 第 2 批：面板与主界面交互（`projects.mjs` + `app/styles/projects.css`）

9. 内联 `MODAL_CSS` 搬进 `app/styles/projects.css`，字号收进 12/11/13 三档，删掉非法的 `font` shorthand；`app/index.html` 引入。
10. 动作重组：head 只留 `＋ 新建项目`（主按钮）+ 搜索框 + `…` 菜单（导入文件 / 导出精灵图 / 刷新降级进菜单）；卡片主操作改为**点卡片即载入**，动作只留 `重命名 / 存为文件 / 删除`（删除用 `--danger`）。**点卡走 `api.open`，守卫只活在 `project-io` 的 `beforeSwitch` 一处**（不把「该不该保存」的判据复制到 UI 层，否则两份判据迟早不一致）；同时 `run()` 的 busy 分支不许静默吞点击（要给 `say('正在载入…')` + 卡片 `is-busy`），守卫浮层出现时项目库浮层降为不可交互。

### 第 3 批：顶栏与帮助（`chrome.mjs` + `help.mjs`）

14. 顶栏项目区加「保存状态」：`名称 •` 保留，但 `title` 补上次保存时间与存储介质（`IndexedDB` / 内存）；未在库时显示 `未命名项目（未入库）`。
15. `help.mjs` 的「文件」组补：`Ctrl+S` 保存到项目库、`Ctrl+O` 项目库、以及「载入前会自动保存已命名项目」这条行为说明。

### 不做

- 不做项目库的云端/多设备（本轮只修本地状态机）。
- 不做 `.msp` 文件与库的双向同步（文件只在显式「存为文件」时写）。
- 不引入 `deletedAt` 软删除字段（撤销用内存暂存即可，避免格式变更）。

## 4. 验收读数（改完必须给）

1. **不再丢**：脏文档 → 点「载入」→ 已命名项目**先入库再载入**（库里该条 `savedAt` 变新、改动仍在库里）；未命名项目弹三选，选「取消」后文档与 `•` 原样保留。
2. **删除可撤回**：删一条 → 出现「撤销删除」→ 点它 → 条目回到原位、`cards` 数复原、`savedAt` 不变。
3. **关窗口有保护**：脏 + 未命名 → `beforeunload` 触发（真机用 `window.dispatchEvent(new Event('beforeunload', {cancelable:true}))` 看 `defaultPrevented`）。
4. **未命名可恢复**：制造未命名改动 → 等自动保存间隔 → 刷新页面 → 出现「恢复草稿」入口，恢复后对象名与之前一致。
5. **面板**：三尺寸（1680/1280/1000×620）浮层 `truncation` 空、`small` 空、字号 ⊆ {11,12,13}；卡片点击即载入（`cardClickLoads:true`）；删除按钮 `--danger`。
6. **顶栏**：脏 → `名称 •`；保存后 `title` 含时间；未入库 → 文案含「未入库」。
7. 全量测试与静态检查通过，新增测试覆盖第 1 批的三条判据与三选分支。
8. **测试绿 ≠ 页面能开**：本轮曾出现 `project-io.mjs` 重复导出（`:693` 与 `:1348` 同时导出 `installProjectSafety`）导致整页 `SyntaxError`，而 `node --test` 仍 809/807/2 全绿、`_check-static.mjs` 仍 73 模块干净 —— 因为测试不 import 该模块、静态检查只验 import 路径存在性、不做语法解析。故本轮补一条硬验收：**改完必须实打 8900**，`index.html` 能加载、`document.querySelector('.top-project')` 非 null、CDP `exceptionThrown` 为零。
