# 向下合并：变换、不透明度与「合成语义单源」

- 日期：2026-10
- 涉及文件：`app/paint/ops.mjs`（`mergeDown`）、`app/editors/layers.mjs`（菜单提示文案）、`tests/ops-merge.test.mjs`
- 对照对象：Klecks（`E:\dev\klecks`，MIT）的图层合并

## 0. 一句话结论

`mergeDown` 原来把上层位图**以单位矩阵**烤进下层，凡上层带变换（位移/旋转/缩放）或 `state.opacity`，
合并后画面立刻变样。修法不是「补一个矩阵乘」，而是**让合并调用 `evaluator.mjs` 的同一个 `drawOne`**：
合成怎么做只由 evaluator 说了算；合并只负责「在哪些时刻采样、把结果写进哪个纹理」。

修完的六组复测全部 0 偏差（唯一例外是「下层自己也带变换」，那是语义边界，见 §6）。

## 1. 缺陷读数（修前 / 修后）

真机脚本 `ms-view/w8-merge-verify.mjs`，40×40 画布、上层红左半 20×40、下层蓝左半 20×40，
`mismatch` = 合并前渲染与合并后渲染逐像素差 > 2 的像素数（共 1600）。

| 场景 | 修前 mismatch | 修后 mismatch | 说明 |
| --- | --- | --- | --- |
| `static_x120` 上层静态 x=120 | 800 | **0** | 上层整块跑到画布外，合并后却回到原点 |
| `rotate90` 上层 rotate=90 | 800 | **0** | 旋转完全丢失 |
| `twoKeys` 上层 0/0.5 两关键帧（x=120 → 0） | 800 / 1600 | **0 / 0** | 两个时刻都错 |
| `pureTransformKey` 只有变换关键帧（x=0 → 20） | 800 / 800 | **0 / 0** | 采样点漏了 t=0.5 这张 |
| `stateOpacity` 上层 opacity=0.5 | 127（maxDelta） | **0** | 半透明被当成不透明烤进去 |
| `lowerOffset` 下层 x=50 | 800 | 800 | **语义边界，见 §6** |

`maxDelta` 在全部修好的场景里都是 0，不是「肉眼差不多」。

## 2. 根因：六件事只做了一件

`core/evaluator.mjs:509-542` 的 `drawOne` 一次做六件事：

1. `state.opacity` × `layer.opacity` × `object.opacity` 三层 alpha 相乘
2. `globalCompositeOperation`（mixMode）
3. `filter`（CSS filter 串）
4. 变换矩阵（含 `baseMatrix` 与父级累乘）
5. `warp`（网格变形）
6. `drawImage`

旧 `mergeDown` 只有第 6 件。所以我一开始想的「把矩阵传进去」本身也是错的 —— 那只补第 4 件，
`warp` / `mixMode` / `filter` 三件照样哑巴亏。

**决定：复制语义就必然抄错，调用它。**

## 3. 修法（`app/paint/ops.mjs`）

```
下层: drawEvaluated(g, ev, at, { ignoreTransform: true })                 // 局部坐标，不含 state.opacity
上层: drawEvaluated(g, ev, at, { baseMatrix: inv(Ml) })                    // 照常，但先反抵消下层变换
```

三个关键点，全部是**既有分支的复用**，`core` 一行没改：

- **`{ ignoreTransform: true }`**（`evaluator.mjs:513` 附近）已经表达了「画在局部坐标里、不吃自己那层的
  `state.opacity`」—— 正是下层需要的语义：下层自己的变换与不透明度要留给写回后由 evaluator 再算一次，
  否则会乘两遍。
- **`{ baseMatrix: inv(Ml) }`**：`evaluator.mjs:521` 是 `m = mulMatrix(o.baseMatrix, m)`，**`baseMatrix` 叠在
  `rec.matrix` 外面**（左侧）。所以传 `inv(Ml)` 就是「先反抵消下层的矩阵，再乘上层自己的」。传 `inv(Ml)·Mu`
  会让上层位移算两次（真机烟测实测 `transform.e = 40` 而不是 20），这条是踩过的坑，写在这里防复发。
- 上层照常走完整语义：`state.opacity`、`mixMode`、`filter`、`warp` 全由 evaluator 处理，与画面一致。

**采样时刻**：`celTimes(上层) ∪ celTimes(下层) ∪ keyTimes(上层)`。
下层的关键帧**不加** —— 下层的变换由写回后的 evaluator 负责，合并只需要「图像内容」变的时刻。
这条分工是有意的：**采样点是「离散 vs 连续」的问题（evaluator 不管），合成怎么算由 evaluator 说了算**，
两者不互相代劳。

**写回**：对每个采样时刻新建一张 `下层图片尺寸` 的面，画完 `setImageAt(下层, at, surf)`，然后把上层从
`doc.objects` 里删掉。撤销命令绑**引用**而不是 id，与落笔同一语义。

## 4. 为什么不再新写一个 merge 专用合成器

- 上游 Klecks 的图层合并在 `src/app/script/klecks/ui/components/...` 下走的是 `klCanvas` 的图层混合，
  同样只有一份语义实现；这里对齐的是同一原则：**画面怎么算，只有一个地方说了算**。
- 一旦 merge 自己写 `drawImage`，`warp`/`filter` 那两条路径就会长期静默偏差，且没有任何测试能发现
  —— 除非再写一份 evaluator 的镜像来做对照。

## 5. 回归护栏（两条，各管一层）

1. **指令级（单测）**：`tests/ops-merge.test.mjs` 第 ② 条不再断言我手算的矩阵，而是**内联复现旧实现**
   （`legacyRecord()`：按 cels 时刻 `drawImage` 到 (0,0)、不碰 CTM），然后断言新实现的
   `surfaces` / `draws` 序列与旧实现**逐条相同**，且新实现的每一笔 `transform` 都是恒等。
   手算期望只能证明「我今天这么想」，快照对照能抓「以后有人改坏」。
2. **像素级（真机）**：`w8-merge-verify.mjs` 的 `LEGACY_GUARD` —— 无变换场景下把旧逻辑真的画一遍，
   与合并结果比像素：`mismatch 0 / 1600`、`maxDelta 0`。

## 6. 已知边界：下层带变换时，合并结果会随下层搬走

`lowerOffset`（下层 `x=50`）修好后仍 `mismatch 800`、`afterOpaque 0`。这不是没修好：

> 合并的真实语义是「**像素落到下层对象的局部坐标里**」。下层带着 `x=50`，那么写回去的图会整体跟着这个
> 变换搬走 —— 合并前你看到的是「上层按自己的变换画、下层按自己的变换画 = 两层各在各的位置」，
> 合并后只有一层，只能有一个坐标系。

这是**用户会误判为 bug 的行为**，所以文档里写不够，必须在界面上让用户看见：
`app/editors/layers.mjs:51` 的合并菜单项提示已改为
「把当前对象合进下一层；**结果会落到下层对象的坐标系**」。

六组复测中「修好后仍 ≠ before」**只允许这一种**。若将来出现第二种，说明还有别的合成环节没接上
（例如新加的属性没进 `drawOne`），应当停下来查，而不是调采样点糊过去。

## 7. 未做但建议做

1. **合并前的确认弹窗**：现在只有 tooltip 一句话。下层带变换时建议弹一次
   「下层带位移/旋转，合并结果会跟着它移动」，并给「取消」。
2. **`objectSize()` 与变换后尺寸不一致**：合并后图片仍是未变换尺寸，属性面板「尺寸」显示的是
   位图尺寸而非视觉尺寸。这是全站性问题，不只合并。
3. **撤销步数与采样点成比例**：一次合并 = 一次撤销（对的），但采样点多时可能触发大图 diff，
   值得在真实 900×640 素材上量一次内存占用。
4. **合并进「组」**：目前没有组概念；一旦引入，`inv(Ml)` 要换成「组的逆矩阵」，届时 §3 的
   `baseMatrix` 仍然是唯一正确的接口，不要另开分支。
