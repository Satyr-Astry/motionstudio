## 1. 一句话定性

**成熟单体、纪律很硬、文档落后一代。** 35k 行原生 ESM、零运行时依赖、无构建步骤，状态内核单写者（`setDoc`）干净，84 个测试文件里大半真的在测算法。问题不在架构，在**「投影被当成真源」这一类缝隙**：屏幕上看不出来，伤害全在存档边界。

## 2. 数据模型真相（v8）

真源是**两张表 + 一条时间轴**，`cels` 只是投影：

| 层 | 真源 | 投影 | 谁维护 |
| --- | --- | --- | --- |
| 纹理资产 | `obj.drawings[]`（`{id,image,...}`，`image` 是 canvas） | — | `addDrawing` / `removeDrawing`（引用计数） |
| 曝光时间轴 | `obj.transform.keys[]` 上的 `key.drawing` | — | `setKeyDrawing` |
| 每格投影 | — | `obj.cels = [{at,image}]` | `syncLibrary` → `projectCels`（**唯一**） |

三个必须记住的性质：

1. `key.drawing == null` **且键存在** = 「这一格是空白」，仍然占一格；`key.drawing === undefined` 才是「这一格不存在」（`keyHasDrawing`，`app/core/doc-model.mjs:922-924`）。
2. 纹理 id 是**会话内身份**：`drawingSeq` 模块级、每次启动从 0 开始（`doc-model.mjs:61`），落盘不带，靠 `drawingIdOf`/`stampDrawing` 重建。所以「按 id 跨存档复用」一定错。
3. 唯一正确的「在某个时刻放一张图」是 `setImageAt(obj,t,image)`（`doc-model.mjs:368-374` = `addDrawing` + `setKeyDrawing` + `projectCels`）。手拼 `{cels:[...]}` 一律是缝。

## 6. 待拍板（第 24 批「效果参数全线动画化」的三个前置决定）

三条都有硬约束，不能分开拍：

1. **颜色参数的轨道怎么存**。颜色现在是任意 CSS 串，`shadow.color` 默认 `rgba(0,0,0,0.45)`（带 alpha），而 `input[type=color]` 只产 `#rrggbb`；单条颜色轨不能复用 `Track`（`normState` 9 字段白名单、`lerp` 纯数值、`mkChannelKeys` 强制 `num()`）。可行解：拆三条数值轨 `fx.tracks['color.r'|'.g'|'.b']`，零 core 改动，只去掉 `effects.mjs:254` 跳过非数值的 `continue`。
2. **插值用 sRGB 直插还是 Oklab**。全仓零颜色空间工具、零运行时依赖，Oklab 要手写 60-100 行；且计划自己的验收判据「RGB 三分量都介于两端之间」——sRGB 直插必满足、Oklab 不保证。**与 1 必须一起定**。
3. **要不要上 GPU**。`app/**` 里 `WebGL|WebGPU|shader` 0 命中，真上 = 从零建管线 + 5 个效果全部重写。计划 §13 自己已列「本轮不做」。
