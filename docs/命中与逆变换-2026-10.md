# 命中测试与逆变换（2026-10）

修复 `修复列表-v8.md` #64 同族缺陷：画布点选的「边界外能选中 / 最右最下一列点不中 / 拖动出界丢帧」。
承接 `docs/画布锚点拖动-2026-10.md`（那里修的是**锚点**命中的坐标形状与反解路径，这里修的是**对象本体**命中的边界语义）。

## 1. 一句话结论

`hitTest` 的边界判定从来不是「点是否在对象内」，而是「`latticeInverse` 把越界点夹到 `[0,1]` 之后是不是还在 `[0,1]` 里」——
夹取让左/上界外 1–2px 算作命中，`Math.floor(uv * w)` 在 `uv === 1` 时又溢出一列/一行让右/下边界像素永远点不中，
两处叠加使「边界」既宽松又残缺。现在改成：按下那一刻把屏幕点严格逆变换到局部坐标，
判 `0 ≤ x ≤ w && 0 ≤ y ≤ h`，容差默认 **0**，像素索引再夹一次。

## 2. 现象（改前）

真机（`http://127.0.0.1:8900/` + Edge CDP，890×640 对象、无变换、1×1 网格、内容全不透明）：

| 方向 | 界内 -3 | -2 | -1 | 边界 0 | 界外 +1 | +2 | +3 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 上边 | 命中 | 命中 | 命中 | 命中 | **命中（错）** | **命中（错）** | 未命中 |
| 下边 | 命中 | 命中 | 命中 | 命中 | 未命中 | 未命中 | 未命中 |
| 左边 | 命中 | 命中 | 命中 | 命中 | **命中（错）** | **命中（错）** | 未命中 |
| 右边 | 命中 | 命中 | 命中 | 命中 | 未命中 | 未命中 | 未命中 |

（`+1` 即界外 1 个 CSS 像素；legacy 列即改造前 `hitTest` 的真实行为，用其源码逐行复刻后跑同一个场景。）

用户侧感受是「点对象外面的空白也能选中它」，且「越往外松手越选不上」——因为 `worldToLocal` 的 bbox 只外扩 `pad = 2`，
到 3px 就返回 `null`，于是行为在 2px 处突变。

拖动侧：`worldToLocal` 一旦返回 `null`，`applyDrag` 那一帧直接 `return`，指针被甩出对象后**整段位移丢失**，画面卡在上一帧。

## 3. 根因（三处叠加）

### 3.1 `quadInverseLocal` 把越界解夹回边界

`app/core/lattice.mjs:239`（改造前）：

```js
if (s < -0.02 || s > 1.02 || t < -0.02 || t > 1.02) return null;
return [clamp(s, 0, 1), clamp(t, 0, 1)];
```

界外 1px 解出 `s = -0.001`，既没超过 `-0.02` 的拒绝线，又被 `clamp` 改成 `0`。
`hitTest` 拿到 `u = 0` 后判 `u < 0` 为假 —— **越界点在夹取后变成了合法点**，命中判定从此失去意义。

### 3.2 `Math.floor(uv * w)` 在 `uv === 1` 时溢出一格

`app/core/element.mjs:305`（改造前）：

```js
const lx = Math.floor(uv.u * size.w);
const ly = Math.floor(uv.v * size.h);
if (pixelAlpha(imageAt(el, time), lx, ly) > threshold) return ...;
```

`uv.u === 1`（正在右边界线上）时 `lx === w`，越界；`pixelAlpha` 对越界返回 `0`，于是**最右一列、最下一行像素永远点不中**。
这一条与 3.1 方向相反：3.1 让界外可点，3.2 让界内不可点。

### 3.3 容差随网格密度与缩放塌缩

`pad = 2` 是世界空间常数，`edge = 0.02` 是**格空间**比例。4×4 网格时一格 25px，`0.02 × 25 = 0.5px`；
放大 2× 时世界空间容差变成 2 个屏幕像素，缩小 0.5× 时变成 0.5px。
同一份「点在手边却没选中」的抱怨在不同网格密度、不同缩放下无法复现——因为容差本来就不是一个固定值。

## 4. 修法

### 4.1 `lattice.mjs`：容差按轴、返回不夹取

- `quadInverseLocal(q, p, tol, edgeX, edgeY)` —— 越界判定改成分轴容差，**返回未夹取**的 `[s, t]`。
- 新增 `latticeInverseRaw(lat, w, h, p, opts)`（`:280`）—— bbox 早退用 `opts.pad`（默认 2），逐格取最近解，返回**未夹取** `[u, v]`。
- `latticeInverse(lat, w, h, p, opts)`（`:312`）保留旧语义（夹取到 `[0,1]`），内部改为调 `latticeInverseRaw` 再夹。
  **默认参数与改造前逐位一致**，变形数学一个字没动。

### 4.2 `element.mjs`：新增 `localUv`，`hitTest` 重写

`localUv(doc, el, time, p, parentM, tolerance)`（`:221`）：

- 先 `invertMatrix(elementLattice(...).matrix)`，把点投进局部空间；
- 1×1 网格且四角零偏移时直接除尺寸（绝大多数对象走这条，零迭代）；
- 否则调 `latticeInverseRaw`，并把 `tolerance` 换算成格空间：`edgeX = max(tol / cellW, 1e-6)`；
- **返回的 `u/v` 不夹取**，调用方自己决定接受范围。

`hitTest(doc, time, x, y, opts)`（`:305`）：

```js
const tol = Number.isFinite(o.tolerance) && o.tolerance > 0 ? o.tolerance : 0;
const loc = localUv(doc, el, time, p, pm, tol);
if (!loc) continue;
const eps = 1e-6;
if (loc.x < -tol - eps || loc.x > w + tol + eps) continue;
if (loc.y < -tol - eps || loc.y > h + tol + eps) continue;
const lx = clampIdx(Math.floor(loc.x), 0, w - 1);
const ly = clampIdx(Math.floor(loc.y), 0, h - 1);
```

三点语义变化：

1. **容差默认 0** —— 按下那一刻的命中范围和视觉边界严格一致，宽容度只能由调用方显式传。
2. **索引夹一次** —— 落在右/下边界线上的点读最后一行/一列像素，不再溢出。
3. **`eps = 1e-6`** —— 亚像素往返误差（实测 `local.y = -2.0000000000000004`）不算越界。

`canvas-input.mjs:38` 的 `hitAt` 同步把 `opts.inside` 从 `worldToLocal` 改成 `localUv(..., 0)`（`:64`），
内部判定不再把越界点当成内部点；锚点路径不受影响（走 `pickAnchor` 纯屏幕距离）。

### 4.3 拖动不再丢帧

锚点拖动已在 `docs/画布锚点拖动-2026-10.md` 换成 `anchorUvFromMatrix`；
本体拖动（`dragPatch` + `writeKey`）本来就不经 `worldToLocal`，但**命中入口**会：
指针出界后 `hitAt` 返回 `null`，`onDown` 就把这次按下当成「点空白」。
现在 `inside` 谓词用 `localUv` 且不夹取，行为与局部坐标一致，不再随 `pad` 突变。

## 7. 与任务描述不符的事实

1. **`hitTest` 不是「容差太严」，而是「两个方向各错一边」**。任务描述写的是「边界外 2px 内能选中」，
   实际左/上放宽 1–2px（越界被夹取），右/下反而**丢失最后一行一列**。只收紧不放宽会留下后半截缺陷。
2. **容差不是常数，是三种东西的乘积**：`pad = 2`（世界像素）、`edge = 0.02`（格比例）、`bestD <= max(1.5, pad)`（距离门限）。
   所以「统一改成 3px」是错的——它必须变成调用方显式给的一个参数，默认没有。
3. **`latticeInverse` 不能直接改**。它被 `worldToLocal` 之外的地方用着（`elementLattice` 的逆在网格拖动里也用），
   改它的夹取语义会连带动网格端点判定，所以新增 `latticeInverseRaw` 承载新语义，老接口原样保留。
4. **「拖动出界丢帧」在锚点路径上已于 #64 修复**（`anchorUvFromMatrix`），本次修的是本体命中入口 `hitTest`/`inside` 谓词；
   两条路径的修法一样（严格逆矩阵 + 不夹取），但不是同一处代码。

## 8. 遗留

### 8.1 `pixelAlpha` 读不到 `ImageBitmap`（新发现，待决策，未修）

真机实测（§5.2）：导入一张 PNG 后，对象的 `image` 是 **`ImageBitmap`**，而

`app/core/element.mjs:269`：

```js
export function pixelAlpha(img, x, y) {
    try {
        return img.getContext('2d', { willReadFrequently: true }).getImageData(x, y, 1, 1).data[3];
    } catch (e) {
        return 0;   // 异常被吞掉
    }
}
```

`ImageBitmap` 没有 `getContext`，抛 `TypeError`，被 `catch` 吞成 `0`。
`hitTest` 的判据是 `pixelAlpha(...) > threshold`，于是**任何以 `ImageBitmap` 为图的对象的中心点都命中不了**
（真机：900×640 全白 PNG 的 `hitTestAt(450,320)` 返回 `null`）。
用户侧表现：导入图片/PSD 图层后，在画布上点它选不中，只能从右侧对象列表选。

对照：`HTMLCanvasElement` 与 `OffscreenCanvas` 的 `pixelAlpha` 都是 255，手绘对象（画格来自 `ensureCelImage` 的离屏画布）不受影响 ——
这也是它一直没被发现的原因：默认对象是 `kind: 'paint'`。

修法方向（未实施，等决策）：给 `pixelAlpha` 加一条 `ImageBitmap` 分支，
用一张 1×1 `OffscreenCanvas` 把该像素 `drawImage` 出来再读 alpha，并按 `ImageBitmap` 缓存；
或退一步让 `hitTest` 对「读不到像素」的对象回退成「矩形命中」。
两种都改变命中语义，且需要新的测试，**不在本次写域内**，故仅记录。
