# P2-C 权重编辑设计（2026-11-02）

**一句话**：给已蒙皮的对象开一个「权重」叠加态，在画布上看见它自己的 25 个顶点、点选、用径向笔刷改 `skin.pts` 的值，一次涂抹一条撤销。**不新增工具、不改 `selection.mode`、不升 `.msp` 版本、不加任何落盘字段。**

这份文档是施工规格，不是方案讨论。每条结论后面都跟了实测行号；与 `docs/骨骼动画方案-2026-11-02.md` 的 P2-C 表述（`:196`「画布上点顶点、radial 刷权重、显示权重重心色」）一致，差异只在 §2 的「不做框选」和 §3 的「不做网格密度切换」，理由写在各自小节。

## 0. 先说三个必须先知道的事实

1. **只改 `skin.pts` 不会触发重绘。** `app/shell/doc-state.mjs:307-323` 的 `sameObjectPixels` 逐字段比了 visible/opacity/mixMode/kind/time/parentId/onionIgnore/anchor/cels/transform/effects，**没有 `skin`**；`commitDoc`（`:364-375`）据此判「像素没变」，`:370` 的 `engine.scheduleRender()` 不会执行。所以 P2-C 第一行代码不是笔刷，是给那个白名单补 `a.skin === b.skin`。不补 = 涂完画面不动，而且会被误诊成命中失败。
2. **`elementLattice` 看不见蒙皮。** `app/core/element.mjs:264-275` 只读 `st.warp`；渲染管线走的是 `app/core/evaluator.mjs:359` 的 `applySkin(...)` 结果。叠加层如果照抄 warp 网格那套（`canvas.mjs:372`）就会把顶点画在未变形位置 —— 这是 `canvas.mjs:369-372` 注释里记着的历史事故的翻版。
3. **撤销窗口不是 650ms。** `DOC_GESTURE_MS = 350`（`app/shell/doc-state.mjs:278`）、`DOC_MERGE_MS = 700`（`:277`）。因此涂抹**不能**依赖 coalesce 合并，必须走「逐帧 silent + 松手推一条命令」的既有范式（`app/editors/canvas-input.mjs:201-204`、`:215`、`:296-304`）。

## 1. 模式开关：叠加态，不是第七个工具

**结论**：权重编辑是「选中带 `skin` 的对象 + 显式打开权重模式」的**叠加态**，不占 `TOOLS` 里的位置。

**理由**（三条，都是改动面）：
- `app/paint/engine.mjs:26-33` 的 `TOOLS` 与 `app/editors/toolbar.mjs:24-31` 的 `TOOL_DEFS` 是**两份重复的手写表**（后者还把中文名写死在源码里，`:25-30`）。加第七个工具要同时改两份表、加图标、加 `tool.weight` 命令，并在 `tests/i18n-parts-commands.test.mjs:52-93` 的 `ID_CONTRACT` 里追加一条（该表**只许追加**，`:51` 注释原话）。
- `downIntent()`（`app/paint/engine.mjs:61-72`）没有「权重」这个分支，未知工具会落到 `:71` 的 `'stroke'` → 直接在纹理上画像素。
- 反过来，`select` 工具下的画布交互**已经全部让给叠加层**：`engine.onDown` 在 `what === 'select'` 时 `:725-728` 直接 `return`，`canvas.mjs:11-12` 的模块注释也写死了这个分工（「工具 = select：全程接管」）。叠加层是这套分工的原生位置。

**落点**：
- 外壳态：`state.weight = { active: false, boneId: null, vertex: null, radius: 0.25, strength: 1 }`，加进 `app/shell/doc-state.mjs:106-119` 的 `state` 字面量（注释风格照 `:111` 那行）。
- ctx 方法：在 `app/shell/app.mjs:557-560`（`bindSkinToSelected` / `unbindSkinOfSelected` 那一组，P2-B 先例）旁边挂 `weightMode() / setWeightMode(on) / setWeightBone(id) / setWeightVertex(i)`。**这几个方法体内必须各自补一句 `canvasEditor.syncSelectionUI()`**：它是叠加层的重画入口（`canvas.mjs:32-36` → `activeBarSync` → `drawGizmo()`，`canvas.mjs:547`），`setSelection` 的收尾就是这么写的（`app.mjs:633-635`）。只改 `state.weight` 不碰文档，`commitDoc` 那条重绘链根本不会跑。`setWeightVertex` 命中的是纯外壳态，同理。
- 进入入口：`app/editors/prop-object.mjs:178-198` 的蒙皮段加一个按钮（`class='prop-seg'`、`dataset.k='weight-edit'`），与「解除绑定」同排；点击先 `ctx.setTool('select')`（复用 `app.mjs:564-567`）再 `setWeightMode(true)`。
- 退出：再点一次、切对象、`skin` 消失、`Escape`（`canvas-input.mjs:155-160` 已有 Esc 取消的口子）。
- 守卫：`setWeightMode(true)` 时若 `skinOf(target)` 为 null，直接 `flash(t('props.obj.weightErrNoSkin'))` 并返回 false。

**相容性**：`downIntent` 一行不改；右键（`button===2` → `'pick'`，`engine.mjs:61-72`）只在 `weightActive` 时被 `canvas-input.mjs` 在 `:362` 的 `if (e.button !== 0) return;` **之前**截获（见 §3 的目标骨选择），其余时间取色语义原样。

## 2. 画布交互：顶点几何自己算，命中原样复用

**结论**：顶点坐标来自新纯函数模块 `app/core/weight-paint.mjs`；命中直接复用 `pickHandle` 的 `lattice` 分支；选中是单选，**不做框选**。

**顶点几何（唯一正确口径）**：
```js
// app/core/weight-paint.mjs
const skin = skinOf(el);
const size = elementSize(doc, el, t);
const M = elementWorldMatrix(el, t, size, parentM);
const base = createLattice(skin.grid.cols, skin.grid.rows);   // 零偏移、同密度
const field = applySkin(doc, el, base, M, size, t);           // 密度相同 → 走 same 分支，不重采样
const map = (u, v) => applyMatrix(M, { x: u * size.w + latticeOffset(field, u, v).x,
                                          y: v * size.h + latticeOffset(field, u, v).y });
```
依据：`app/core/skin.mjs:377` 的 `same = L.cols === cols && L.rows === rows` 分支直接取偏移场（`:384-393` 才走 `latticeOffset` 重采样），所以传同密度 `createLattice` 得到的是**逐顶点精确**的蒙皮偏移，没有二次插值误差；`applyMatrix` / `elementSize` / `elementWorldMatrix` 都在 `app/core/element.mjs`（导出见 `:27`、`:163`）。

**绘制位置**：`app/editors/canvas.mjs:drawGizmo` 里插在 `:334 drawBones(g)` 之后、`:336-337 const info = selectionInfo(); if (!info) return;` **之前**。
必须在判空之前：用户可能只选中了骨骼（想换目标骨）而没选中蒙皮对象，此时顶点仍要显示。`drawBones` 当初就是为同一个理由放在 `:333-334`（注释 `:333` 原话「它要常显，所以必须在 selectionInfo() 判空之前」）。

**顶点方块**：尺寸直接用 `HANDLE_PX`（`app/core/gizmo.mjs:37` = 4，屏幕像素常量）—— 与 warp 顶点的 `drawSquare`（`canvas.mjs:358-366`）完全同参，天然不随 zoom 缩放（命中半径同理用 `HIT_PX`，`:38` = 9）。骨骼线宽那套 `max(2,min(48,width*z))`（`canvas.mjs:208`）是给骨头用的，不要套到顶点上。

**网格线**：按 `map(u, v)` 采样，照抄 `canvas.mjs:379-393` 的写法，`N = 1`（skin 网格 4×4 已有 25 个点，再细分只会糊）。**禁止**用 `latticeWireframe`（`app/core/lattice.mjs:318-345` 返回的是**已含偏移的局部像素**，画之前会再被 `map` 采样一次 = 偏移两遍），事故记录在 `canvas.mjs:369-372`。

**命中**：复用 `pickHandle`，它的 `mode==='warp' && lattice` 分支（`app/core/gizmo.mjs:120-133`）就是「遍历 (cols+1)×(rows+1) 个顶点、屏幕距离 ≤ threshold、同距取后者」，而且 `:136-147` 已经处理了「顶点命中不能短路整体手柄」的坑。
落点：`app/editors/canvas-input.mjs:hitAt`（`:41-76`）里，当 `state.weight.active` 为真时把 `opts.lattice` 换成 skin 网格的 `{cols, rows, map}`（现在是 warp 网格，`:47-55`），返回 `{ kind: 'weight-vertex', vertex }`；`zoneOf`（`app/core/warp-drag.mjs:201-209`）不受影响（它按 `kind` 分流）。`onDown`（`:361-414`）在 `:374` 之前插一个 `weight-vertex` 分支：`ctx.setWeightVertex(v); e.preventDefault(); e.stopPropagation(); return;`。

**为什么不做框选**：`docs/骨骼动画方案-2026-11-02.md:221` 已经把「顶点笔刷到像素级、权重平滑、镜像」划进「不做」；框选属于同一类批量工具，成本是 `pickInRect` + 一个新的拖动态 + 一组测试，而 P2-C 的目标是「手动修自动权重错的地方」，逐点足够。

## 3. 权重怎么写：补足法，不是「改一根再归一」

**结论**：以指针所在参数坐标 `(u,v)` 为中心做椭圆衰减，把**目标骨**的权重朝 1（加）或 0（减）插值，**其余骨按比例补足**，最后交给 `normalizeSkin` 收口。

**算法**（`app/core/weight-paint.mjs`，纯函数，零 DOM）：
```js
paintWeights(pts, grid, u, v, radiusU, radiusV, boneIndex, amount, mode)
// mode: 'add' | 'subtract' | 'smooth'
```
1. 每个顶点算 `dist = hypot((c/cols - u)/radiusU, (r/rows - v)/radiusV)`，`strength = mode === 'smooth' ? smoothFalloff(dist) : max(0, 1 - dist)`。`max(0,1-dist)` 与 `app/core/warp-drag.mjs:84` 的 `strength = Math.max(0, 1 - dist)` 同形（这里**不复用** `warpAllocation`：它返回的是 `alpha` 格点重分配系数，语义是「位移怎么摊」，不是「权重多少」，硬套会得到看似正确实则错位的衰减）。
2. `t = strength * amount`；该骨当前权重 `w`，目标 `target = mode==='subtract' ? 0 : 1`：`wNew = w + (target - w) * t`（`smooth` 时取邻域均值，不做）。
3. 其余骨同步缩放：`wOther *= (1 - wNew) / max(1 - w, 1e-9)`；若该骨原本是 `w === 1`，其余骨直接归 0。
4. 该骨写回 `wNew`，然后整体过 `normalizeSkin`（`app/core/skin.mjs:276-286`）收口：截 4 根、降序、Σ=1、`!(w>0)` 的项被剔除（`:181-200`）。

> **落地时的顺序修正（`0.5.0-alpha.25` 实测）**：上面第 3–4 步的顺序在「顶点已有 4 根骨、目标骨是第 5 根」时不成立——刚刷出的小权重会被 `normalizeSkin` 的降序截断立刻丢掉，表现为**刷半天界面毫无反应**。实现改成**先截骨数再算缩放**：其余骨降序截到 `SKIN_MAX_BONES_PER_POINT − 1 = 3` 根，被剔除的权重按 `spread = otherSum / keepSum` 摊给保留项，再乘 `scale = (1 − wNew) / max(1 − w, 1e-9)`。效果相同（最后都过 `normalizeSkin`，Σ 精确 = 1、单调收敛），但目标骨恒在 4 项内。详见 `docs/修复列表-v8.md` §1an 第 241 条。

**为什么不能「只改这一根、再让归一化去补」**：`normalizeSkin` 是按 Σ 等比缩放（`skin.mjs:198`）。若只把 b0 设成 0.8、其余不动（假设原 `{b0:0.5,b1:0.3,b2:0.2}`），归一后会变成 `{b0:0.615,…}` —— 用户刷 0.8 却得到 0.615，而且**连续刷两次都到不了 0.8**（每次都被别人的历史值稀释）。补足法保证「单骨权重是用户看到的绝对值」，这是权重笔刷能被接受的前提。

**目标骨从哪来**（两级）：
- 显式：`state.weight.boneId`。来源 ① 面板骨列表（`prop-object.mjs` 蒙皮段，列出 `skin.bones[].id` 对应对象的 `name` + 主骨色圆点）；② **画布右键径向菜单** —— 在 `canvas-input.mjs:onDown` 的 `:362` 之前加分支：`if (e.button === 2 && weightActive) { e.preventDefault(); e.stopPropagation(); openBoneRadial(e); return; }`。这是唯一的右键语义替换，且被 `weightActive` 严格围栏。
- 兜底：没有显式目标时按「最近骨」临时取一根（`app/core/skin.mjs:421-470 autoWeights` 的 `distToSegment` 逻辑，目前 `distToSegment` 是模块私有 `:400-408`，需要追加 `export`），并 `flash(t('props.obj.weightAutoBone'))` 告知用户「这次刷的是哪根」。

**网格密度**：P2-C **不动** `skin.grid`（保持 `SKIN_DEFAULTS.grid` 4×4，`skin.mjs:37`）。`resampleWeights`（`skin.mjs:209-265`）只在将来加「改密度」时用，且必须遵守 `:271-273` 的约定：先重采样再写回，绝不让 `normalizeSkin` 去凑。

## 4. 写入口与撤销粒度：逐帧 silent，松手一条命令

**结论**：一次拖动 = 一条撤销，实现照抄网格软拖。

**做法**（`app/editors/canvas-input.mjs`，新增 `startWeightDrag` / `applyWeightDrag` / `endWeightDrag`，与既有三段一一对应）：
- 起手记 `drag.before = doc`（同 `:124-152` 的 `startDrag`）、`drag.base = skinOf(el).pts`（深拷一次，后续每帧都从 base 重算，避免误差累积）。
- 移动（rAF 节流，同 `:162-174`）：算出新 `pts` → `writeSkin(doc, elId, pts)` → `ctx.setDoc(next, { silent: true, label: t('props.obj.weightPaint') })`。对照 `:205-224` 的 lattice-soft 分支（`:215` 就是这一句）。
- 松手（`:256-339` 同族）：补最后一帧后推一条命令，**照抄 `:296-304` 的双保险形态**：
  ```js
  const cmd = { label: t('props.obj.weightPaint'),
      undo: () => ctx.setDoc(before, { silent: true }),
      redo: () => ctx.setDoc(after,  { silent: true }) };
  if (ctx.engine && typeof ctx.engine.pushCommand === 'function') ctx.engine.pushCommand(cmd);
  else if (ctx.engine && ctx.engine.history) ctx.engine.history.push(cmd);
  ```
- 取消：Esc（`:155-160`）→ `ctx.setDoc(drag.before, { silent: true })` + `ctx.requestRender()` + `ctx.notify(t('props.obj.weightCanceled'))`，对照 `:289-293`（既有代码在回落后确实补了一次 `requestRender`，因为 silent 写入不必然触发重排）。

**为什么要 `pushCommand` 而不是 `engine.history.push`**：`engine.pushCommand`（`app/paint/engine.mjs:911-914`）= `history.push(cmd)` **加** `emit('history')`；`history.push` 只入栈不广播，顶栏撤销按钮的可用态要等到下一次别的刷新才更新。`canvas-input.mjs:302-303` 已经写成「优先 pushCommand、拿不到才回落」，照抄即可。

**为什么不用 coalesce**：`setDoc` 的 `*auto` 窗口是 `DOC_GESTURE_MS = 350`（`doc-state.mjs:278`），显式 `coalesce` 是 700（`:277`，取用于 `:411-413`）。刷得慢时两次独立拖动会被合并成一条撤销，撤销粒度随手感漂移 —— 这正是 `doc-state.mjs:408-410` 注释描述的「一次拖动灌满撤销栈」问题的反面。

**写入函数**（`app/shell/app.mjs` 里与 `bindSkinToSelected` 同族的唯一写口）：
```js
function writeSkinPoints(layerId, pts) {
  const doc = state.doc;
  return patchObject(doc, layerId, (o) => Object.assign({}, o,
      { skin: normalizeSkin({ ...skinOf(o), pts }) }));
}
```
`patchObject` 来自 `core/cel.mjs`（结构共享，与 `app.mjs:1236` 的绑定写法同构）；`normalizeSkin` 来自 `core/skin.mjs:276`。

**这里刻意不写 `ctx.requestRender()`**：`pixelsDiffer` 是 `doc-state.mjs` 的私有函数（导出清单在 `:988-1032`，没有它），app.mjs 里拿不到；而且**修好 §9-1 之后根本不需要** —— `setDoc` → `commitDoc` → `pixelsDiffer(prev,next)` 为真 → `:370` 的 `engine.scheduleRender()` 自然会跑。把重绘交给那条链路，才不会在「拖动时每帧手排一次渲染」上白烧帧。

## 6. 落盘：一个字都不用改

**结论**：`.msp` **不升版本、不加字段、不改序列化代码**。

依据：
- `app/shell/project-store.mjs:54` `VERSION = 4`；`:48-53` 的注释明确把「骨骼 + 蒙皮」写进「故意不升」的清单（纯增量字段，旧版读新档只丢字段不崩）。
- `skin` 早已在两处白名单里：落盘 `:416-419`、读入 `:750-752`，两侧都过 `normalizeSkin`。
- P2-C 只改 `pts` 的**值**，字段集与语义不变，`tests/skin.test.mjs:460-481` 的往返断言已覆盖。

**唯一要写进注释的语义**：`normalizeSkin` 会剔除 `!(w > 0)` 的项（`skin.mjs:181-200`），所以「把这根骨刷到 0」= 删除该顶点上的这一项，不是存一个 0。这是**正确行为**（省空间、`hasTracks` 类判据更干净），但要写进代码注释，否则下一个人会以为数据丢了。

## 7. 测试策略

**能纯函数测（`node --test`，无 DOM）**：衰减曲线、补足法、归一结果、顶点几何、命中判定、序列化往返。
**只能 `npm run smoke`**：叠加层是否真的画出来、右键径向菜单弹不弹、拖动是否跟手。
`tools-smoke.cjs` 已经是「不挂 preload 的窗口里加载 app/ 并轮询 15 个编辑器」的现成闸门（`tests/ipc-contract.test.mjs:4-5` 记着它的盲区是 main/preload，不是 UI）。

**断言清单（10 条，写成「断言 X 等于 Y」）**

1. 断言 `paintWeights([{b:0,w:0}], {cols:1,rows:1}, 0, 0, 1, 1, 0, 1, 'add')[0]` 等于 `[{ b: 0, w: 1 }]`。
2. 断言两骨 `[{b:0,w:0.5},{b:1,w:0.5}]` 对 b0 刷 `amount=1`、`radius` 覆盖该点后，`normalizeSkin` 的结果 `[0]` 等于 `[{ b: 0, w: 1 }]`（`length === 1`，补足法把 b1 压到 0 后被过滤）。
3. 断言 `strength(dist=0) === 1`、`strength(dist=1) === 0`、`strength(dist=2) === 0`（不出负值）。
4. 断言同一顶点连刷两次 `amount=0.5` 后 `w` 严格递增且 `< 1`（`w2 > w1` 且 `w2 < 1`）。

## 9. 三处最容易返工 / 最可能静默的地方

**1. `sameObjectPixels` 缺 `skin`（`app/shell/doc-state.mjs:307-323`）。**
这是**静默型**：涂抹逻辑、命中、归一全都对，画面就是不动。而且症状会被误判成「命中失败」或「`ctx.setDoc` 没生效」，白白烧掉半天。修法一行：在 `:321` 的 `a.effects === b.effects` 之后补 `&& a.skin === b.skin`（结构共享，引用比较足够；`patchObject` 产出的新对象 `skin` 引用一定变）。回归锁 = §7-9。

**2. 顶点位置口径（`elementLattice` 不含蒙皮）。**
`app/core/element.mjs:264-275` 与 `app/core/evaluator.mjs:359` 是两个不同的网格：前者是 `st.warp`，后者是 `st.warp + 蒙皮偏移`。用前者画顶点 → 用户看到对象已被骨骼拉走、顶点却停在绑定姿势，点不中的正是「眼睛看到的位置」。`canvas.mjs:369-372` 的注释记着同一个模块上一次就是这么错的（网格线与顶点错开，用户报障）。守卫 = §7-6 的对拍断言，它比任何肉眼验收都可靠。

**3. `state.weight` 与文档失同步（悬空 `boneId` / `vertex`）。**
切对象、删骨、解绑、`redo` 都会让 `boneId` 指向不存在的骨或越界的顶点下标。`normalizeSkin` 会把 `b >= boneCount` 的项**静默剔除**（`skin.mjs:181-200`），于是「刷了没反应」——又一次静默失败。落点：在 `commitDoc`（`doc-state.mjs:364-375`）之后、或 `subscribeDoc` 回调里做一次 `syncWeightState(doc)`：`boneId` 不在 `skinOf(el).bones` 里就置 null 并 `flash`；`vertex` 超过 `(cols+1)*(rows+1)-1` 就置 null；对象 `skin` 消失就直接关模式。判据写法参照 `doc-state.mjs:252-265 clampSelection`（选择态自愈）与 `app.mjs:594-601 selectedLayers` 的「自愈过滤」先例。
