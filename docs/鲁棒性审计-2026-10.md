## 二、v1–v3 缺 `fps` 的存档按 1 fps 打开

### 现象

打开早期（v1/v2/v3 帧模型）保存的项目，画面能出来，但**播放速度只有应该的 1/12**、时间轴刻度全错、导出出来的视频时长也跟着错 12 倍。面板上看不出任何异常 —— 文件里没有 `fps` 字段，界面显示的就是「当前文档的帧率」，用户无从对比。

### 根因

`app/core/doc-model.mjs` 里有一对互相抵消的写法：

```js
// :35
function clampNum(v, lo, hi) {
    const n = Number(v);
    if (!Number.isFinite(n)) return lo;   // ← 非有限数返回的是「下限」
    return n < lo ? lo : n > hi ? hi : n;
}

// :811（旧）
const fps = clampNum(old.fps, 1, 120) || 12;
```

`old.fps` 缺失时 `clampNum(undefined, 1, 120)` 返回的是 **下限 1**（不是 `NaN`，也不是 `undefined`），于是 `||` 右边的 `12` **永远拿不到**。`fps: 0` 同样被夹成 1。

### 影响面

- 打开后 `doc.fps = 1`：播放慢 12 倍；时间轴刻度、吸附网格（按秒换算）全部错位；导出时长错 12 倍。
- 只影响**帧模型旧存档**（`version` 缺失或 ≤ 3）。真实 v4 存档（`format: "motionstudio-project"`）走 `docFromTimeNode → docShell`，压根不经过 `migrateFromFrames`，所以**不受影响** —— 用真实存档 `项目-20261024-1757.msp` 复测：`fps 12 / duration 3 / 900×640 / 1 个对象`，改前改后完全一致。

### 修法

先判「有没有一个正的帧率」，再交给 `clampNum`；缺省走 12。没有新增工具函数。

```js
const fpsRaw = Number(old.fps);
const fps = Number.isFinite(fpsRaw) && fpsRaw > 0 ? clampNum(fpsRaw, 1, 120) : 12;
```

### 同形状排查

`rg "clampNum\([^)]*\)\s*\|\||clampInt\([^)]*\)\s*\|\|" app` 全仓只有两处：

- `app/core/doc-model.mjs:811` —— **本缺陷，已修**；
- `app/editors/timeline.mjs:391` —— `clampNum(Number(next) || zoomX, …)`，`||` 在**内层**（先兜底再 clamp），语义正确，**保留不动**。

### 测试

`tests/robust-doc-shape.test.mjs`：

- v3 缺 `fps` → 12；
- v3 `fps: 0` → 12；
- v3 `fps: 24` → 24；
- v3 `fps: 999` → 120（上限仍在）；
- `undefined / null / '' / 'abc' / NaN / -Infinity` 六种坏输入一律 12（这条同时给未来留一句注释：别再在本层写 `clampNum(...) || 兜底`）；
- 真实 v4 形状 → `fps 12 / duration 3 / 900×640 / 1 个对象` 全部不变。

## 三、P1-1：导入快照跨 `await`

**旧行为**：`importFileObjects` 把 `state.doc` 的快照交给 `pickAndImport`（要按快照算居中与新对象插入位置），文件对话框是异步的；回来以后 `commitImportedDoc(res.doc)` **无条件整体替换**当前文档。对话框期间如果文档被换过（切项目、撤销/重做重建文档），用户这段时间的改动就被旧快照覆盖掉了。

**新行为**：落库前先判「快照还是不是当前文档」——
- 是（`canReplaceDoc` 为真）：走**原来那条整体替换**，行为零变化；
- 不是：`mergeImportedDoc` 只把**当前文档还没有的对象**并到最前面，其余字段一律用当前文档的。

**取证**：`main.js` 的 `dialog.showOpenDialog(win, …)` 传了窗口，Windows 上是**窗口模态**，所以现实里这条路径很难撞上 —— 但那是「平台行为恰好挡了一部分」，一旦改成非模态对话框或拖拽导入就立刻可触发。这也是为什么按「顺手加一层判断」而不是「重做导入流程」处理。

**测试**：`tests/robust-import.test.mjs`（7 例）—— 同一对象才算有效快照、内容相同但换引用算过期、只并新对象且排最前、文档其它字段不被旧快照改回、没有新对象时原样返回当前文档（不制造空 `setDoc`）、兼容旧 `layers` 容器、`id` 按字符串归一、脏输入不抛。

## 四、P1-2：读入的画布尺寸没有上限

**旧行为**：`docShell` 用 `Math.max(1, Math.round(posNumber(node.width, FALLBACK.width)))` —— 只有下限，**没有上限**。手改过或第三方生成的 `.msp` 写 `width: 100000` 会被原样收下，`fitView` 把画面缩成一个点，用户看到的是一片灰。

**新行为**：再套 `Math.min(4096, …)`，下限保持 **1**（历史文件里有 1×1 的，抬到 16 会让它们打不开）。

**关于上限取 4096 而不是 8192**：任务里写的是「与 `createDocument` 的 `clampInt(16, 8192)` 对齐」，但代码里查不到 8192 —— 仓库里真正的尺寸上限是 **4096**（`app/core/doc-model.mjs:297-298` 的 `Math.min(4096, …)`、画板 `BOARD_MAX = 4096`、属性输入框 `input.max = 4096`）。按「与仓库既有一致」取 4096，**就写 4096 这个字面量，不引入新常量**（与 `:297-298` 的既有写法一致）。

同一轮把 `createDoc`（`app/core/doc-model.mjs:135-136`）也补上了同一个上限 —— 它原来只有 `Math.max(1, …)`，意味着**从代码入口造出来的文档**可以超过画板能表示的范围。现在「从任何入口造出来的文档」都不超过 4096，下限保持 1。

**测试**：`tests/robust-doc-shape.test.mjs` —— `100000` → 4096；`1` → 1；正常值 1280 与缺省 900 都不变。

**未单独验证**：clamp 之前「导出 PNG 会不会因超大画布失败」没有去证 —— clamp 之后这条路不存在了。

## 五、P2-1：偏好文件逐项校验

**旧行为**：`setPrefs` 的注释写着「只合并已知键」，实现却是 `Object.assign({}, prefSnap, next)` —— 未知键会进来，已知键的值也不校验。手改出来的 `undoLimit: "abc"`、`objectW: 1e9` 一路进到引擎。

**新行为**：清洗逻辑抽到 `app/core/prefs.mjs`（纯函数、零依赖，node 里可直跑），`setPrefs` 合并后过一遍 `cleanPrefs`：
- 只认 `autoSave / undoLimit / snapGrid / objectW / objectH / bg` 六个键，其它全部丢掉；
- 数值只接受「数字」或「非空数字字符串」。`Number('')`、`Number([])`、`Number(null)` 都是 0，直接 `Number()` 会把空值悄悄变成合法的 0，反而看不出文件坏了；
- `undoLimit`（上限 2000）、`objectW/objectH`（上限 4096）要求**正值**，0 与负数退回缺省而不是夹到下限 —— 夹出「1 步撤销」「1×1 的对象」比退回缺省更糟；
- `bg` 只放行 `^[a-z][a-z-]{0,15}$` 的标识符。

**测试**：`tests/robust-prefs.test.mjs`（11 例）。

### P2-1b：偏好面板改的「对象默认尺寸」重启后失效

这不是「从没生效」，比那更难发现：**当次会话一直是好的，重启之后悄悄回缺省。**

- 面板改动 → `prefs.sizeW` → `applyPrefs()` → `setPrefs({ objectW: prefs.sizeW, … })`，这条链本来就是对的。真机读数：把「自定义宽」填 640 → `prefObjectSize()` 立刻变 `{w:640,h:640}`。
- 断的是**存盘与启动恢复**：`prop-prefs` 往 `localStorage['ms.prefs']` 存的是 `sizeW/sizeH`（它自己那套键名，还带 `sizePreset`），而启动时 `doc-state.loadPrefs()` 从**同一个 key** 读、交给 `cleanPrefs` 时只认 `objectW/objectH` → 读到 undefined → 退回缺省 900。用户看到的是「改完是好使的，重启之后又变回去了」。

**修法**：外部存储双写 + 读取双向兼容（不动面板内部字段名 —— `prefs.sizeW` 有 9 处引用，牵着 `sizePreset` 语义、两个 CSS 变量与输入框回填）：

1. `cleanPrefs` 认 `sizeW/sizeH` 作 `objectW/objectH` 的别名，新键优先、旧键兜底，坏值照旧退回缺省；
2. `prop-prefs.readPrefs` 用 `o.objectW != null ? o.objectW : o.sizeW`；
3. `prop-prefs.commit` 写入时带镜像 `{ ...prefs, objectW: prefs.sizeW, objectH: prefs.sizeH }`，旧键原样保留。

**真机闭环**（`w13-prefs3.mjs`）：遗留的 localStorage 只有 `{sizePreset:'custom', sizeW:640, sizeH:640}` → `prefObjectSize()` 读出 `{w:640,h:640}`（旧键迁移生效；改前这里会是 900）→ 面板改成 700 → `lsNow` 变成 `{sizeW:700, sizeH:640, objectW:700, objectH:640}`（双写）→ `loadPrefs()` 模拟重启 → 仍 `{w:700,h:640}`。

**测试**：`tests/robust-prefs.test.mjs` 加两条 —— 旧键迁移（含坏值退回缺省）、新键优先（且新键坏值不挡旧键）。

## 六、P2-2 / P2-3 / P2-4：只记录

**P2-2 `setDoc` 在 updater 抛异常时静默保留旧文档**（`app/shell/doc-state.mjs:345-389`）。它其实**打了一行 `console.error`**，不算完全静默；而且 updater 抛错还让文档前进，风险更大。**不改**。

**P2-3 父子环**。`a.parentId = b, b.parentId = a` 时 `elementWorldMatrix` 返回全 `null` 矩阵、`hitTest` 返回 `null`、`createEvaluator` 0 层 —— **不崩，但对象静默不可见**。用户会看到「对象消失」。修它要在 `elementWorldMatrix` 里加环检测（多一次 visited 集合分配，每次求值都跑）。**不改**，进待修清单。

**P2-4 `docShell` 少写 `duration`**。`duration` 非法时 `docShell` 不写这个字段，消费点（`docState` 的 `setTime`、`timegraph`）各有兜底，所以不出错；但「同一个字段有时在、有时不在」会让后续读入代码写起来更小心。**不改**：`project-store.mjs` 的文档构造牵着 `.msp` 往返测试。

## 八、审计过程中读出来但确认「没问题」的部分

- **`JSON.parse` 全仓 10 处，没有一处无守卫**：`persist.mjs` 是样板级（localStorage 访问 + 解析 + 形状 + 版本号逐层 try，`LS_VER = 3`）；`project-io.mjs` 的 `importProjectFile` / `loadProject` 各有 try 与用户可见提示；`prop-prefs.mjs` 的 `readPrefs` 是逐项白名单样板；`layers.mjs`、`timeline-keys.mjs` 的 `snapGrid` 读取都带 try。剩下的三处 `JSON.parse(JSON.stringify(x))` 是深拷贝。
- **`jsonToDoc` 对 22 个恶意 payload 一个都没抛**：`null / 字符串 / 数字 / {} / objects 非数组` 全部拒绝返回 `null`；`objects 里空对象 / key 的 t 是 NaN 或字符串 / state.x 是 NaN / 循环引用 / 信封 / 锚点越界 9e9 / 父级自指 / 互为父 / fps 0 + duration NaN / 深嵌套 200 层` 全部被条款级兜底接住，最终文档里没有 `NaN` 字段。
