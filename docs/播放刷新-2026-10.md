# 播放刷新分级（P0 #12）

结论：播放期间的刷新原先**名义上分两级、实际走同一条路**——`full` 只进统计、不进判断，
当前工作区 5 个面板照样每个都 `refresh()`。这次把「谁真的跟时间走」逐面板取证后做成
纯决策函数（`app/shell/refresh-plan.mjs`），并在降级的那一刻补上**播放停止必须全量刷一次**
（改前完全没有，这是个真 bug）。

代价：一次多文件改动；收益：40 对象场景每秒面板耗时 **99.7ms → 35.5ms（−64%）**，
`layers` 从每秒 30 次降到「跨画格才刷 + 停一次」，且**暂停后属性面板显示的是停止时刻的值**
（改前会停在旧值上）。

---

## 1 判据：谁跟时间走

分级不能凭猜。判据只有一条——**这个面板的 `refresh` 里读不读 `ctx.time()`**（含它转发出去的
子面板）。逐个读过之后的事实：

| 编辑器 | 读时间？ | 依据（代码位置） |
| --- | --- | --- |
| `canvas` | 是 | `editors/canvas.mjs:420` → `selectionInfo()` 在 `:166-167` 用 `ctx.time()` 算锚点/选框 |
| `board` | 是 | `editors/board.mjs:1414` → `texture()`（`:157`）用 `imageAt(obj, timeNow())` 取当前画格 |
| `timeline` | 是 | `editors/timeline.mjs:190` `const now = timeNow()`，播放头位置随它变 |
| `curve` | 是 | `editors/curve.mjs:315` → `stateAt(track, nowTime()).warp`、`:364` 当前值圆点 |
| `properties` | 是 | `editors/properties.mjs:86` 转发给 `xform.mjs:60-62` / `prop-object.mjs:431,484`，数值框显示 `stateAt(track, time)` |
| `layers` | **按画格** | `editors/layers.mjs:796` → `syncRows(doc, active, selectedId(doc), nowTime())`；缩略图是「当前生效画格」的图（`:242` 注释写明），画格内连续时间变不影响 |
| 其余（`doc` / `onion` / `info` / `prefs` / `help` / `projects` / `toolbar` / `palette`） | 否 | `prop-onion.mjs:68` 只读 `doc.onion`、`prop-info.mjs:15` 只读文档统计、`help.mjs:213` 是空函数 |

所以分级是三档，不是两档：

- **全量**：文档变了（`setDoc` / 切工作区 / 切项目 / 撤销重做 / 属性提交）
- **时间档**：只有时间在推（播放、拖播放头），只刷上表 5 个 + 画格换了才带 `layers`
- **不动**：与时间无关的面板，一个都不刷

## 2 实现

### 2.1 `app/shell/refresh-plan.mjs`（新增，纯决策，node 可直跑）

```
TIME_DRIVEN_EDITORS = Set(['canvas','board','timeline','curve','properties'])   // :29
CEL_GRANULAR_EDITORS = Set(['layers'])                                          // :32
planRefresh(editors, opts) -> { run, skip }                                     // :42
celSignature(objects, time) -> '对象数,画格0,画格1,...'                          // :72
```

`planRefresh` 的判据就是上面那张表：全量档全放行；时间档只放行 `TIME_DRIVEN_EDITORS`，
`layers` 仅在 `celChanged` 时放行。**非字符串 id 直接跳过**（不做 `String()` 转换——数字
混进来只说明调用方给错了，静默转字符串会刷错面板，这条是测试抓出来的）。

`celSignature` 把「每个对象当前处在第几个画格」压成一个字符串。它只在**跨过画格边界**时变，
所以拿它做 `layers` 的刷新闸门：连续时间推进不重画缩略图，切画格才重画。

### 2.2 `app/shell/doc-state.mjs`

- `:43` 引入 `planRefresh, celSignature`；`:652` 新增 `let lastCelSig = ''`
- `refreshPanels`（`:720`）重写：先把当前工作区的 slot 摊平成数组（`:734-744`，整片跳过隐藏工作区
  的既有逻辑保留），`:724` 算签名、`:745` 出计划，再按 `quota` 逐槽扣名额——
  **同一个编辑器开了两个面板时两个都要刷**，所以配额是「次数」不是「集合」。
  被跳过的计入 `state.refreshStats.skipped`（`:752`，只统计、不参与逻辑）。
- `setPlaying`（`:582`）停止分支末尾 `if (!want) scheduleRefresh();`（`:602`）——见 §5。

## 3 改前 / 改后（同机器、同尺寸 1680×1000、12fps、5s）

计数由 `window.motionStudio.state.refreshStats` 给出（`calls` 刷新轮次 / `panels` 面板刷新次数 /
`fullCalls` 全量轮次）。播放 1 秒采样：

| 场景 | 改前 | 改后 | 变化 |
| --- | --- | --- | --- |
| 3 对象 · 每秒面板刷新次数 | 145 | 120 | −17% |
| 3 对象 · 每秒面板耗时 | 50.9 ms | 56.2 ms | 单次耗时噪声（见 §7.2） |
| 12 对象 · 每秒面板耗时 | 69.6 ms | **40.9 ms** | **−41%** |
| 40 对象 · 每秒面板耗时 | 99.7 ms | **35.5 ms** | **−64%** |
| 40 对象 · `layers` 每秒耗时 | 59.5 ms（30 次） | 2.0 ms（1 次） | **−97%** |
| 停止时补全量（`fullCalls` 增量） | **0** | **1** | 修掉 §5 的 bug |

掉帧数：三档 rAF 都是 60 帧 / `maxGap 16.8ms` / `long 0`，改前改后一致（本机在这个规模不掉帧，
见 §7.3）。

## 4 「跨画格才刷」的真机证据

测试项目里默认对象只有一个画格，签名恒定，`layers` 播放期间**一次都不刷**——这是正确行为，
但看不出粒度。所以另造两组对照（`ms-view/w5-cel.mjs`，monkey-patch `layers` 的 `refresh` 计数）：

| 场景 | 画格签名采样 | 播放中 `layers` 刷新 | 累计（含停止补刷） |
| --- | --- | --- | --- |
| 空对象（1 个画格 `at=0`） | `1,0` ×4（去重后 1 种） | 0 次 | 1 次 |
| 两画格（`at=0` / `at=0.5`） | `1,0`,`1,0`,`1,0`,`1,1`,`1,1`（2 种） | **1 次**（t 跨过 0.5 那一下） | 2 次 |

即：`layers` 的刷新次数 = 播放中跨画格次数 + 停止补刷 1 次；改前是每秒固定 30 次。

## 5 顺手修掉的真 bug：停止时不补全量

改前 `scheduleRefresh({timeOnly:true})` 的 `full` 标记纯粹是统计用途，两级执行同一条路，
所以「只刷时间类」这件事**从来没生效过**，也就没暴露一个后果：一旦真的只刷时间类，
**暂停那一刻属性面板会停在播放中的旧值**（时间类面板刷的是「当前时间」，而用户此刻要看的是
「停止时刻」的冻结值）。

所以 `setPlaying` 停止时补 `scheduleRefresh()`（`doc-state.mjs:602`，不带 `timeOnly` → 全量档）。
真机验证见 §6 场景 4。

## 7 与任务描述 / 直觉不一致的地方

1. **「改前是两级刷新」不准确**：`refreshPanels` 的 `full` 只进 `refreshStats.fullCalls`，
   两档执行完全相同的循环（改前 `:712-746`）。所以这不是「分级没做好」，是**分级不存在**。
2. **3 对象档的耗时反而略升（50.9 → 56.2ms）**：这一档只有 5 个面板、单次耗时都在 0.2–1.1ms，
   `layers` 原本也只占 7.8ms，省下的量级小于测量噪声（同脚本重复跑有 ±10% 波动）。
   收益在 12 / 40 对象档才显现，报告里不该拿 3 对象档当收益证据。
3. **本机 40 对象也不掉帧**（`long 0`、`maxGap 16.8`）：P0 说的「掉帧」在 1680×1000 / 本机上复现不出来。
   能复现的是**每秒白刷的面板次数**（355 次/秒 → 116 次/秒）与**耗时**（99.7 → 35.5ms）。
   掉帧定性需要更弱的机器或更重的面板才能验证，本文不给这个结论。
4. **`layers` 在默认空对象上等于「永不随播放刷新」**：因为默认对象只有一个画格。
   一旦对象有多个画格，它就会跟着画格切换刷（§4 已验证）。这不是漏刷。
5. 任务要求「判定口径写进代码注释」——注释写在 `refresh-plan.mjs` 文件头与每个集合上方，
   逐模块列了理由，不是一句「与时间无关」。
