# 术语表

> 一句话：**用户看到的地方只说「纹理」和「曝光」，代码里的字段名保持原样。**
> 换字段名等于升数据格式版本（`.msp` v4 已发布），代价远大于收益，所以术语统一只做在文案层。

## 1. 映射表

| 用户可见术语 | 数据字段 / 代码标识 | 旧术语 | 说明 |
| --- | --- | --- | --- |
| **纹理** | `drawing` / `drawings[]` / `drawingId` | 画格 | 一张位图本身。它没有时刻，只有内容；同一个纹理可以被多个时刻引用。 |
| **纹理库** | `doc.drawings` 资产表 | 画格库 | 文档里所有纹理的集合。引用计数到 0 时会被回收。 |
| **一次曝光** | `cel` / `cels[]` | 画格（在时间轴语境下） | 「某个纹理在某个时刻开始生效」这条记录。它指向一个纹理，自身不存像素。 |
| **曝光时刻** | `cel.at` / `key.t` | 画格时间 | 这条记录生效的起点（秒）。 |
| **加曝光** | 追加 `cels[]` 条目 | 加画格 | 时间轴语义：在某时刻让某个纹理开始生效。措辞保留「曝光」，因为它描述的是时间行为。 |
| **画布 / 纹理尺寸** | `image.width` / `image.height` | — | 纹理自身的像素尺寸，与画布（`doc.width/height`）不是一回事。 |

## 2. 为什么字段名不改

`cel`、`cels`、`drawing`、`drawings` 这些名字已经写进 `.msp` 存档格式（v4）与所有历史项目文件。
改字段名必须同时改读入侧的兼容层、升格式版本号、并处理旧存档迁移 —— 那是格式变更，不是术语变更。
所以约定是：

- **用户可见文案**（界面、提示、帮助、文档正文）只用「纹理」；
- **数据字段与代码标识**保持 `cel` / `drawing` 原样，永不因为「叫法变了」而重命名；
- 代码注释里提到用户概念时优先写「纹理」，需要指字段时写字段名本身（如 `cels[]`）。

`docs/**` 的正文（除 `修复列表-v8.md` 的历史条目，它在文件头加了注记）、`tests/**` 的测试标题与断言消息。
