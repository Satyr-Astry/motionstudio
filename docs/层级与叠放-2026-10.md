# 层级与叠放（α 方案）· 执行契约 2026-10

本文件是这一批的**唯一契约**。改动与它冲突时以它为准；要改契约先改这里，再改代码。

## §0 结论（为什么这样拆）

调研证据：Spine 把「骨骼层级」与「Draw Order 列表」当两套数据（[Slots](https://esotericsoftware.com/spine-slots)）；
Toon Boom 明确说「在 Timeline 里拖图层会打断父子关系，要在 Node 视图里改合成端口顺序」
（[Ordering Layers in the Node View](http://docs.toonboom.com/help/harmony-24/premium/rigging/order-layer-node-view.html)）；
Aseprite 把 cel 当图层属性、编辑入口在 `Layer > Properties`（[Layers](https://www.aseprite.org/docs/layers/)）；
After Effects 的父级只是每行一个下拉，与叠放顺序无关。

所以我们拆成三件事：

| 概念 | 谁管 | 数据 |
| --- | --- | --- |
| 层级（跟谁动） | `app/core/hierarchy.mjs` | `object.parentId` |
| 叠放（谁盖谁） | `app/core/draw-order.mjs` | `doc.drawOrder: string[]`（index 0 = 最上层） |
| 纹理（对象的图） | `app/core/textures.mjs` | `object.cels` + `doc.drawings` |

三者互不代偿：改层级**不动** `drawOrder`，改叠放**不动** `parentId`。

## §1 数据契约

- `doc.drawOrder` 是对象 id 的数组，**集合必须与 `doc.objects` 的 id 集合恒等**（无漏、无重、无未知 id）。
- 缺字段（老文件、旧调用方造的 doc）→ `normalizeDrawOrder(objects, src.drawOrder)` 用 `objects` 现有顺序派生一次；幂等。
- 顺序语义：`drawOrder[0]` 画在最上面；渲染从数组尾往头画（等价于现有 `composite` 的逆序循环）。
- 序列化：`.msp` 的时间节点新增 `drawOrder: [...]`（与 `elements` 同级）；读回时同样走 `normalizeDrawOrder`。

## §2 模块与 API

`app/core/draw-order.mjs`（纯函数零 DOM）

- `normalizeDrawOrder(objects, order) -> string[]`
- `drawOrderOf(doc) -> string[]`（缺字段时现算，不改 doc）
- `orderIndex(doc, id) -> number`（找不到返回 -1）
- `moveInOrder(order, id, index) -> string[]`
- `insertInOrder(order, id, index) -> string[]`
- `removeFromOrder(order, id) -> string[]`

`app/core/hierarchy.mjs`（纯函数零 DOM）

- `parentChainOf(doc, obj)` / `collectSubtree(doc, id)` / `isDescendant(doc, target, maybeAncestor)`
- `treeOrder(objects) -> string[]`（DFS 展示序，只用于树面板显示，**不是**叠放序）
- `normalizeParents(objects) -> objects`（悬空父置 null、断环、深度上限 64）

`app/core/textures.mjs`（纯函数零 DOM）

- `texturesOf(obj)` / `textureAt(obj, t)` / `textureTimes(obj)` / `textureCount(obj)`
- 写操作一律继续走既有 ctx（`resizeTexture`、`placeDrawing`、`addDrawing`、`setImageAt`），本模块只读。

`ctx` 新增（`app/shell/ctx-time.mjs`）

- `drawOrder()` → `doc.drawOrder`（已规整）
- `orderIndexOf(id)` → number
- `moveDrawOrder(id, index) -> boolean`：一次 `setDoc`，`label:'调整叠放顺序'`
- 既有 `setParent` / `moveSubtree` 改为**只改 `parentId`（+ 保位置换算）、不碰 `drawOrder`**

## §3 一致性规则（每个写入口都要遵守）

1. 新建对象：`drawOrder` 插到 index 0（最上层）。
2. 删除对象：从 `drawOrder` 移除；其子对象 `parentId` 置 null（保持既有语义）。
3. 向下合并：结果保留下层对象的 id 与它在 `drawOrder` 的位置，上层对象移出。
4. 复制对象：整棵子树复制，新块插在源块**正上方**，内部相对顺序保持。
5. 导入（PSD/PNG/`.msp`）：按导入序（top-first）生成 `drawOrder`；`.msp` 有 `drawOrder` 则用之，否则按 `elements` 顺序派生。
6. 加载/迁移：`normalizeDrawOrder` + `normalizeParents` 各跑一次，幂等。
7. 撤销/重做：仍然靠文档快照，两处顺序天然一致，不额外记账。

## §4 渲染

`app/paint/composite.mjs`、`app/core/evaluator.mjs`、导出三条路径（PNG 序列 / 精灵图 / WebM）一律按 `drawOrder` 遍历；取不到 `drawOrder` 时回退 `objectsOf(doc)` 的顺序（等价于老行为）。**不允许**在两处各写一份排序。

## §5 界面

- `layers` 区域：标题「叠放」，**纯扁平列表**——无缩进、无折叠、无缩略图；行 = `名称 · N 纹 · 不透明度 · 可见性`；拖拽 = 只改 `drawOrder`。
- 新区域 `tree`：父子树——只编辑 `parentId`（拖到行上=成为子对象，拖到空白=脱父）；显示缩进、折叠、「N 个子对象」；**不表达叠放顺序**（不允许在这里拖行间）。
- 属性面板新增「纹理」组（排在「对象」之后、「变换」之前）：当前时刻纹理缩略图（40×40，双击进画板）+「共 N 张 · 当前第 k 张 · 曝光 M 处」+ 四个动作（新建 / 独特化 / 删除 / 裁到内容）+ 画布尺寸两数字框与「重设」。
- 默认布局：编排左列上 `tree`（约 180）下 `layers`；画板左列 `layers` + `palette`（画板不需要树）；设置工作区不变。

## §6 术语

用户可见文案、文档、注释一律用「纹理」：`纹理 → 纹理`、`纹理库 → 纹理库`、`加曝光` 保留（曝光是时间轴的语义）。

数据字段**不改名**（格式稳定）：`cels`、`drawing`、`celTimes`、`setImageAt` 保持原样；文档与代码注释里写明「cel = 纹理的一次曝光记录」。术语统一由 Lead 在最后一遍集中做，避免并行改动撞车。

## §7 验收

- `drawOrder` 与 `objects` 的 id 集合恒等；`orderIndex` 与数组位置一致。
- 叠放操作不改变任何 `parentId`；父子操作不改变 `drawOrder`（各 20 次操作后逐项比对）。
- `save → load → save` 两处顺序逐项一致；缺 `drawOrder` 的老文件读入后派生正确。
- 随机 200 次混合操作（叠放/父子/删除/合并/复制）后不变量恒成立。
- 渲染顺序可测：三对象红绿蓝叠放，改 `drawOrder` 后画布中心像素颜色随之变化。
- 每次操作一条撤销；`npm test` 与 `npm run check`（静态 + 语法）全绿；三尺寸审计 `small/unlabeled/symbolOnly/truncation/errors` 全 0。

## §8 本轮不做

`drawOrder` 的关键帧（叠放随时间变）、纹理独立资产库面板、嵌套与叠放分组（`group` 概念）、跨文档复制粘贴。
