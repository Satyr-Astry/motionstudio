## 2. 问题一：属性面板的纹理管理

### 2.1 用户原话

> 属性中的纹理管理有问题，不能选择当前纹理等。

### 2.2 现状取证（2026-11-02 实读代码）

「纹理」组是属性面板段一里的第二组（`app/editors/properties.mjs:16` 的 `ORDER = ['object','textures','xform',…]`），由 `app/editors/prop-textures.mjs` 渲染。它现在只有五样东西：

| 位置 | 内容 | 是不是交互 |
|---|---|---|
| `prop-textures.mjs:166` | 40×40 缩略图（`thumbnail`，双击切工作区的入口另说） | 只读 |
| `:175` | 一行摘要「共 N 张 · 当前第 k 张 · 曝光 M 处」（`textureSummary` 在 `:59`） | 只读文本 |
| `:182` | 四个动作按钮：新建 / 独特化 / 删除 / 裁边（`TEXTURE_ACTIONS` 在 `:43`） | 有 |
| `:197` | 画布尺寸宽高两个数字框 | 有 |
| `:207` | 重设尺寸 + 对齐三档 | 有 |

**没有任何「纹理列表」，也没有「选中/切换到第 N 张」的入口。** 全仓搜 `ptx-list` / `tex-list` / `textureList` / `drawingList` 均 **0 命中**。这就是用户说「不能选择当前纹理」的直接原因：摘要告诉你「当前第 3 张」，但你没有任何地方能点第 1 张或第 5 张。

### 2.3 现在到底怎么换纹理（三条迂回路径，用户很难发现）

1. **把播放头移到另一个「换图时刻」**：时间轴上带实心小方块的键就是换图点（`timeline-paint.mjs:769-772` 的 `.has-drawing`）。但用户得先知道「哪一帧换了图」。
2. **快捷键/命令**：`Shift+,` / `Shift+.` = `goPrevCel` / `goNextCel`（`app/shell/app.mjs:1486/1491`，定义在 `:457/:468`），跳到相邻的纹理时间点。
3. **命令面板里两条**：`cel.cycle-prev` / `cel.cycle-next`（`app.mjs:1527/1533` → `cycleDrawing` 在 `:1246`）—— **这两条才是真正的「按库顺序切上一张/下一张纹理」**，但**没有默认快捷键**，只能从命令面板搜。

### 2.4 历史原因（为什么变成这样）

v8 把「纹理块」从时间轴上彻底移除了 —— `timeline-paint.mjs:13` 的注释写得很清楚：

> 纹理块已移除：纹理挂在关键帧上，换图看 `.tline-kf.has-drawing`

也就是说：**v8 之前时间轴上有可点的纹理块，移除后没有在属性面板补一个等价入口**。`prop-textures` 只补了「摘要 + 动作」，漏了「选择」。这是回归，不是从来如此。

### 2.5 顺带发现的两个小缺陷（读代码确认，非真机）

- **删除只能删「当前那张」**：`runDelete`（`:348`）把 `deleteCandidateId(ids, cur, null)`（`:135`）的第三参恒传 `null`，于是候选顺序退化成「当前 → 最后一张」，用户无法指定删哪一张、也删不掉「未被引用的废图」。
- **「新建」不给尺寸选择**：`runNew`（`:321`）直接 `ctx.newDrawing(obj.id)` 再 `placeDrawing`，尺寸取外壳缺省；想建 2048×2048 得建完再改。

### 2.6 建议方案（按代价排序，任选其一作为第一批）

**方案 A（推荐，最小）：「纹理条」列表**

在摘要与动作之间插一行横向缩略图条：每张库里的纹理一个小方块（当前那张高亮）+ 序号，**点一下 = `ctx.placeDrawing(obj.id, now, drawingId)`**（已有 API，见 `cycleDrawing` 的用法 `app.mjs:1257`）。再给每张方块一个右键/长按菜单：独特化、删除这张、在画布上显示。零新数据模型，全部复用现有命令。

**方案 B（完整）：「纹理抽屉」**

点击摘要展开一个列表（缩略图 + 尺寸 + **被哪些时刻引用**（`textureTimes(obj)` 已有）+ 引用计数），支持选中、插入到当前时刻、删除未被引用的。代价：新增一个 DOM 结构 + CSS（`app/styles/textures.css` 已有 `.ptx-*` 命名空间）。

**方案 C（顺手）**：给 `cel.cycle-prev/next` 补默认快捷键（`[` / `]` 空着），并在帮助面板的时间组登记 —— 不是解药，但能让「有这功能」被发现。

### 2.7 验收（真机 + 自动化各一半）

- 手测：建 3 张纹理（`cel.new` 三次）→ 属性面板点第 1 张 → 画布与缩略图立刻变成第 1 张 → `Ctrl+Z` 一步回退。
- 自动化：抽纯函数（比如「列表项数组 + 当前 id → 高亮项」）写 node 测试；面板接线用源码守卫（参照 `tests/ik-panel.test.mjs` 的写法）；`npm run smoke` 必须仍 15/15。
- 记账：账本新一节 + CHANGELOG + 版本 +1 修订（纯 UX 修复，批次不加）。

### 3.3 已确认的两个具体 bug

1. **卡片上「纹理时间点数」永远不显示**。
   `projects.mjs:434-443` 的 `metaLine(r)` 判断的是 `r.cels`，而记录里根本没有 `cels` 字段 —— `makeRecord`（`project-store.mjs:1058` 起）写的是 `frames`（`:1077`：`frames: times.size`），`stripRecord`（`:1092` 起）透传的也是 `frames`。
   → `if (r.cels)` 恒 undefined，那一项被静默跳过。**一行就能修**（`r.cels` → `r.frames`），顺手加一条测试。
2. **顶栏「保存」的语义是「入库」，不是「存文件」**，但界面上没有任何地方说清。
   用户从桌面应用的习惯出发会以为 Ctrl+S 保存了 `.msp`；实际上外部文件只在「存为文件」时写一次，之后再 Ctrl+S 不会更新它。
   → 这是「重大缺陷」里**最容易让人丢工作成果**的一条：打开文件 → 改 → Ctrl+S → 看到「已保存」→ 关掉 → 磁盘上的文件还是旧的。

### 3.4 根因

- **产品层面**：项目库（IndexedDB）与项目文件（`.msp`）是**两套身份**，但 UI 只有一个「保存」按钮，语义没对齐；
- **架构层面**：`project` 状态里 `id`（库身份）与 `file`（文件路径）是两个字段，`saveProject` 只更新前者，没有任何「若有 file 就一并写回」的分支（`project-io.mjs:821-837`）；
- **历史层面**：项目库最初是「浏览器里的草稿箱」，后来才加「存为文件」，但没回头把「文件优先」的桌面工作流补上。

### 3.5 建议路线（按「防丢数据」优先，不按功能好看排序）

**P0（防丢失，1–2 天）**

1. 修 `metaLine` 的 `r.cels` → `r.frames`（一行）+ 测试；
2. 顶栏/菜单把「保存」与「存为文件」的差异写明（`title`/提示语），并在**项目有 `file` 时**让 `saveProject` 顺手写回该文件（新增 `ipc.saveProjectTo(file, json)` 或复用 `ms:save-project` 带 `file` 参数；主进程 `main.js` 的 handler 在 `:327` 附近）；

**P1（补齐「项目」该有的动作，2–4 天）**
