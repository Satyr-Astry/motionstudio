# 画板图标与可读性计划（2026-10-25）

> 只出计划，本轮不改代码。所有尺寸都是真机读数（只读副本 8900 + CDP 9334，窗口 1400×900 与 1000×620 两档），代码行号对应当前 `main`。

## 0. 结论

用户说的「可以用图标的控件非要用文字，即便用文字也不显示完全」，落到画板上是三件不同的事，混在一起改只会互相抵消：

1. **7 支笔用单字缩写**（`像 圆 软 铅 晕 散 擦`）——这不是「文字」，是**被剪掉的文字**。单字既不构成词，也不指向语义（「像」是像素还是图像？「晕」是晕染还是模糊？），每换一支笔都要试。
2. **小窗口把文字藏掉、又没给替代**——`@media (max-width:1100px)` 里 `.bd-act > span{display:none}` 与 `.bd-field > .bd-lab{display:none}`，于是「＋纹理／独特化／适配」变成三个无字图标（22×22），两条滑杆失去名字。**用户看到的「显示不完全」就是这一条**，而且是我上一轮为了压宽度加的降级，属于我造的债。
3. **裸数字与标签混排**——同一行里「`大小` ▬▬ `12` `不透明` ▬▬ `100`」，滑杆与数字之间没有从属关系，读数要靠猜哪个数字属于哪根杆。

结论：**不是「该用图标的地方用了文字」，而是「该是图标的位置放着残字，该是文字的位置被藏掉了，该分组的地方没有分组」。** 所以本计划的主线是「图标归图标、文字归文字、两者都不许被静默裁掉」。

## 2. 根因

- **单字来自 `BRUSH_SHORT`**（`app/editors/board.mjs:56-58`，取值 `name.slice(0,1)` 的兜底）：为了在 26px 高的工具条里塞下 7 支笔。宽度确实省了，代价是每次选笔都要读 `title`。
- **文字被「删掉」，不是被截断**：`app/styles/board.css:351-366` 的 `@media (max-width:1100px)` 里有两条 `display: none` —— `:352` 的 `.bd .bd-act > span`（收掉「纹理/独特化/适配」三串字）与 `:363` 的 `.bd .bd-field > .bd-lab`（收掉「大小/不透明」两个标签）。这正是用户说的「即便用文字也不显示完全」：窗口一窄，文字直接不存在，只剩三个语义不明的图标和两根没有名字的滑杆。而 `.bd-lab` 本身是 `10px`（`board.css:86`），已经是全站最小一档。
- **这是上一轮宽度补丁造的债**：当时只验证了「1000×620 下不溢出」（内容 782 → 726，容器 760），没验证「藏掉之后还认不认得」。**能放下 ≠ 可读**，判据缺了这一半。
- **参数混排**：`bd-field` 的 DOM 是「label + range + number」三段紧邻、无分隔，两根杆之间只有 `gap`。四段文字与两个数字等距排列，属于「分组缺失」而不是字体问题。

## 4. 三类处理规则（本计划的核心）

给每个控件判定一次「它属于哪一类」，判定依据固定为四条，避免以后再来一轮反复：

- **A 类 = 纯图标**：有行业通用符号（取色器、填充、撤销、重做、删除、左右切换、适配视图）。
- **B 类 = 图标 + 名称**：产品自造概念，或**同一类工具的多实例**（7 支笔）。多实例尤其不能只给图标——7 个形状相近的笔尖图标，用户记不住谁是谁，Klecks 那边也是「每支笔一张缩略图**加名字**」而不是光秃秃的图标。宽屏文字可省成两字短名，窄屏收成纯图标时 `title` + `aria-label` 必须在，且窄屏有浮动名可看。
- **C 类 = 纯文字 / 图标 + 数字（不许纯图标化）**：① 要读的数字（稳定器档位、滑杆数值、纹理计数）② 用户自己起的名字（对象名、笔刷自定义名）③ 多态且无公认符号的选择（镜像四向）④ 指引下一步的句子（空态文案、底部键位提示）。
- **D 类 = 动都不动**：浮层标题、说明句、"告诉用户接下来做什么"的文案。

按这四条，画板上的控件分布是 **A 类 8 个、B 类 10 个（7 支笔 + 纹理/独特化/适配）、C 类 5 个、D 类 3 个**。

> 我最初把这 7 支笔判成 A 类（纯图标 + tooltip），后来改判 B 类。理由写在上面第二条：它们不是「7 个互不相干的动作」，是「同一支笔的 7 种形态」，光靠图形区分等于让用户背 7 张图。
