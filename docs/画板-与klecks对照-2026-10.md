## 0. 一句话结论

画板之前没有右键取色，根因不是「少一个功能」，而是**右键这个手势在画板里没有归属**：引擎把右键让给了舞台的平移语义
（`app/paint/engine.mjs:690` 原先 `if (e.button === 2) { panStart(e); return; }`），画板自己只认左键
（`app/editors/board.mjs` 原 `pointerdown` 首行 `if (e.button !== 0) return;`）。
Klecks 的取色器把右键定义成「**临时工具触发器**」——工具本身不变，松开就回来。照这个语义补齐即可，不需要新增工具、不需要改状态机。

第二批（同日）：**手抖**是同一类根因的另一面——画板原本把 `pointermove` 的点直接当落笔点，中间没有任何「输入姿态」层。
补的是 Klecks 的档位滞后曲线（`app/paint/stabilizer.mjs`，纯函数零 DOM，0–5 档），画板只在落笔采样处调用、不进 `setDoc`/撤销栈。
真机量化（§7.3）：同一条手抖轨迹，level 5 的笔迹包围盒从 **21 px 收到 8 px**、中心线拐点 **3 → 1**、轨迹两端没被截短。

第三批（同日）：**油漆桶**。之前判「未做」的理由是生命周期不清（换纹理/换纹理时可能写错图）。答案是把它压成同一个同步块、并让撤销命令绑 canvas 引用（§8.2）；真机上「在 B 纹理填充 → 切回 A 纹理逐像素不变」已经证实（§8.3）。

### 2.3 与 Klecks 的语义差异（有意为之）

| 场景 | Klecks | 我们 | 为什么 |
|---|---|---|---|
| 点在透明像素 | 返回 `rgb(0,0,0)`，**把黑色取走** | 返回 null + 提示「这个像素是透明的，没取到色」 | 画板的底是透明的，把「空」当黑色是错的 |
| 点在纹理外 | 返回黑 | 提示「点在纹理外面了，没取到色」 | 同上 |
| 当前时刻没有纹理 | — | 提示「这个时刻还没有纹理，没得取色」 | 这是 MotionStudio 特有的状态（时刻 ↔ 纹理） |
| 工具状态 | 临时槽位 | 一个布尔 `rightPick`，不写 `brushId` | 画板没有「工具」概念，只有 7 个笔刷 chip |
| 取色与撤销栈 | 只改 `brushSetting` 的颜色，不进 history | 同左：只改当前色，不 `pushCommand` | 取色不是编辑文档的动作；进栈会让 Ctrl+Z 变成「退回上一支笔」。口径已写进帮助（`app/editors/help.mjs:28`） |

## 7. P0（第二批）：笔迹稳定器 0–5 档（已落地，2026-10-25）

### 7.1 Klecks 的档位与语义（取证）

| 位置 | 事实 |
|---|---|
| `src/app/script/klecks/ui/components/toolspace-stabilizer-row.ts` | 工具栏一行 `<select>`：0 / 0.5 / 1 / 1.5 / 2 / 3 / 4 / 5，滚轮也能改，`LANG('stabilizer')` |
| `src/app/script/klecks/events/hybrid-line-smoothing.ts:19-52` | 0–2 档走 `LineSmoothing`（smoothing ≈ level×0.3 一带的映射）；3/4/5 档切换成 `LegacyLineSmoothing`，系数 `1-0.035` / `1-0.0175` / `1-0.00875` |
| `src/app/script/klecks/events/line-smoothing.ts:5` | 源码注释：「Lag on a straight line = smoothing / (1 - smoothing) events」——**它的档位本质就是「滞后多少个采样事件」** |

### 7.2 我们的实现（`app/paint/stabilizer.mjs`，新文件）

- 公式 `yₙ = yₙ₋₁ + (xₙ - yₙ₋₁)·α`；α = 1 即 level 0 **完全直通**（既有手感逐位不变，有用例锁）。
- 档位按 Klecks 的「滞后事件数」对齐：level 1…5 → α = 0.60 / 0.40 / 0.25 / 0.14 / 0.07，稳态滞后 0.67 / 1.5 / 3.0 / 6.14 / 13.3 事件（Klecks 对照值 0.43 / 1.5 / 2.33 / 5.25 / 27.6，见 `stabilizer.mjs` 头注释表）。
- **最小移动阈值**：亚像素抖动不落点，且不把阈值一点点吃掉——否则 level 5 站着不动也会吐点。
- 只输出「这一笔该往哪走」，不碰纹理、不碰 `setDoc`、**不进撤销栈**；落笔仍是一次 `pushCommand`。
- 有意为之的差异：单级滤波 + 按 `pointermove` 采样（画板落笔自带间距插值 `spacingPx()` + carry，中间点由落笔侧补）；Klecks 是四级串联。所以我们的 level 5 比 Klecks 同级「跟手」，再慢就会明显跟不上手。

接入点（`app/editors/board.mjs`）：`pointerdown` 建 stabilizer（`:734`）、`pointermove` 采样（`:757`）、`pointerup` 用 `stabTail` 追平线尾（`:786`）后 `reset()`（`:788`）；`setStabLevel`（`:1090`）写 localStorage `ms.board.stabilizer`（`:51`，非法值由 `clampLevel` 收口）；UI 是 `.bd-bar` 右端按钮（`:328`，`.bd-stab` + `.bd-stab-n` + `is-on` 态），点击循环 +1（`:1097`），`Ctrl+滚轮` 调档（`:1175`）。

样式说明：`.bd-stab` / `.bd-stab-n` **目前没有专门 CSS**（沿 `.bd-ico` 继承），所以图标与档位数字贴得偏近。类名与需求（间距 / `tabular-nums` / `is-on` 激活态）已列给 Lead，由 Lead 在 `app/styles/*` 补——本批不动样式文件。

## 8. P1：油漆桶填充（已落地，2026-10-25）

§9 表格里原本写着「未做，理由见第 6 条」。第 6 条当时的判断是「生命周期不清，别塞半成品」。本轮把这条判断落到可执行的形式，实现随之成立。

### 8.1 Klecks 的语义（逐条取证）

| 事实 | 出处 |
|---|---|
| 工具只在**左键** `pointerdown` 时触发一次填充：屏幕点逆变换到图像坐标后 `Math.floor` | `ui/easel/tools/easel-paint-bucket.ts:35-45` |
| 光标是 `cursor-fill.png`，热点 `(1,12)` | 同上 `:36`、`:58` |
| 干活的是 `kl-canvas.floodFill(layerIndex, x, y, rgb\|null, opacity, tolerance, sampleStr, grow, isContiguous)`；越界或 `opacity === 0` 直接 return；有选区且起点在选区外则不填 | `canvas/kl-canvas.ts:884-910` |
| 容差默认 **51/255**（UI 显示 20%，`value: 20 * (255/100)`），滑杆 0–255 | `ui/tool-tabs/fill-ui.ts:58-67` |
| 容差判定是**逐通道平方差 ≤ tolerance²**，四个通道（含 alpha）都要过 | `image-operations/flood-fill.ts:31-46` |
| 「全图替换」不是修饰键，是 `isContiguous` 参数（UI 是开关）；另有 `grow`（扩张半径）与 `sample`（`above`/`current`/`all` 取样范围） | `kl-canvas.ts:884`、`kl-app.ts:694-705` |
| 橡皮模式下传 `rgb = null`，即「用填充做擦除」 | `kl-app.ts:696` |

### 8.2 我们的实现

`app/paint/fill.mjs`（新，纯函数、零 DOM、`node` 直接 import）：

```js
export const DEFAULT_TOLERANCE = 24;
export function parseHex(hex) -> [r, g, b, 255]
export function floodFillRegion(data, w, h, sx, sy, hex, tolerance = 24) -> { changed, painted }
```

- 容差语义**照抄 `engine.mjs:598-657`**（不是照抄 Klecks）：双方 `alpha === 0` 直接算匹配，否则只在 `alpha > 0` 时逐通道比，填完 alpha 写 255。这样画板与舞台两处填充对「透明区」的理解一致，不会出现同一份画在两边填出不同形状。
- `board.mjs` 只负责接线，逻辑不进 `setDoc`：`G` / 桶按钮切 `bucketMode`（这是**模式**，和 `E` 的临时工具不是一条分支），左键 `pointerdown` → `fillAt(e)`，全程同步，无 `await`/`rAF`。

生命周期问题（§9 第 6 条当时的顾虑）的答案，落在 `fillAt` 的 5 步之内：

```
1. img = textureForFill()          // 'none' | 'bitmap' | <canvas>
2. before = captureRegion(img, 全图)      // 引用，不是像素副本之外的任何间接寻址
3. g.getImageData(...) → floodFillRegion → g.putImageData(...)   // 同一个 g
4. after = captureRegion(img, 同上)
5. pushCommand(makeRegionCommand(img, before, after, '填充（纹理）'))
```

第 1 步拿到 `img` 之后，2–5 全在同一个同步块里，中间没有任何可被插入的调度点，而 `setDoc` 的重渲染只能在 `pointerdown` 返回之后跑 —— 所以结构上不存在「算出 A 的填充、写进 B」的窗口。撤销命令绑定的是**那张 canvas 的引用**而不是对象 id，与落笔（`board.mjs` 的 `endStroke`）同一语义，事后切纹理、换纹理、删对象都不会写错图。

两类「点不动」被拆成两句提示，因为它们是不同性质的事：

| 情况 | 提示原文 |
|---|---|
| 这个时刻没有纹理 | `这个时刻还没有纹理：点「纹理」新建一张` |
| 纹理是导入位图（`ImageBitmap` 没有 `getContext`） | `这张纹理是导入位图，暂不支持填充` |

条件 2 之所以要显式拆开：合并成一句，用户会以为是自己少做了什么。

## 10. 未做但建议做

1. **触屏等价**：Klecks 有 double-tap / 长按手势（`updateDoubleTapPointerTypes`）。画板目前右键只在鼠标上成立，触屏用户没有取色入口。
2. **`Alt` 与宿主窗口**：Alt 取色已实现（见 §3），但要确认 Electron 主窗口没有把单独的 `Alt` 当菜单键吃掉——`Alt+左键` 的按键组合本身在 Electron 里不会触发菜单，真正的风险是「单独按 Alt 再点击」，需要在 Electron 里再验一次（本轮只在 Chromium 页面里验过）。
3. ~~**取色的撤销语义**~~：取色不进 `pushCommand`（改的是当前色，不是文档），与 Klecks 一致。这条口径已写进帮助（`app/editors/help.mjs`「取色只改当前色，不进撤销栈」）与 §2.3。
4. **`pickBtn` 与 `rightPick` 的状态联动**：目前右键取色会顺手把 E 取色器关掉（`setPickMode(false)`）。若将来支持「锁定取色器」，这行要重新审视。
5. **`engine.mjs` 画板模式**：`boardImage()` 依赖的 `isDrawingBoard()` 在当前 UI 上恒 false（§4）。要么接上，要么把这条死路径标注清楚，别让下一个人以为它在工作。
6. ~~**油漆桶为什么这轮不做**~~ → **已做，见 §8**。当时判定「生命周期不清」是有价值的判断，落地的形式是：把「取纹理 → 连通域 → 回写 → 两次 `captureRegion` → 一条命令」压进同一个同步块，并让撤销命令绑 canvas 引用而不是对象 id（§8.2）。仍未做的是 Klecks 的 `isContiguous`（全图替换）、`grow`、`sample`、不透明度与橡皮模式（§8.5）。
8. **填充的键盘入口只有 `G`**：`help.mjs` 的键位表里一直写着「填充 G」但代码里没有实现——这次把它兑现了。顺带暴露出表里另一处不一致：表里写「橡皮 E」，而画板里 `E` 实际是**取色器**（`I` 在画板不生效）。这不是本轮引入的，改它要动 `help.mjs` 与 `board.mjs` 的键位映射两处，留给下一轮统一。
7. **稳定器是「单级低通 + 按事件采样」**：Klecks 是四级串联 + 单事件多采样（`passes: 4`）。我们靠落笔侧的间距插值补中间点，所以高档位下笔迹的「点密度」由 span 决定，不是由稳定器决定。若将来要更接近 Klecks 的拖尾质感，得在稳定器内部加多级级联（数据结构不变，只是 `push` 内多跑几级），属于纯函数改动、不碰 UI。
