# 画布锚点直拖（修复列表 #64 未完成项）

> 目标：在画布上直接拖动对象的**旋转原点（锚点）**，不再只能靠属性面板的数字框 + 「居中」按钮。
> 范围：`app/core/gizmo.mjs`、`app/editors/canvas-input.mjs`、`app/editors/canvas.mjs`，外加 `tests/canvas-anchor.test.mjs`。

## 1. 结论先说

`#64` 记的「画布上不能拖旋转原点」在仓库里**不是「没实现」，而是「实现了但永远命中不到」**：锚点命中分支早在初始提交（`e49787f`）就在，`git log -S "kind: 'anchor'"` 只命中那一条，但那一行取错了坐标的形状，判定恒为 `false`，于是每次按在原点上都落到同位置的 `nw` 缩放手柄，表现成「拖原点 = 把对象压扁 / 翻转」。

本次把它修通，并补齐拖动期间的三条交互契约（预览、Esc 取消、一次拖动一条撤销）。

## 2. 真因：两处独立的缺陷

### 2.1 命中判定取错了坐标形状（恒 false）

修复前 `app/editors/canvas-input.mjs`：

```js
const aScr = toScreenArr(applyMatrix(elementWorldMatrix(el, time, size0, parentM), anchorPoint(el, size0)));
if (aScr && Math.hypot(p.sx - aScr[0], p.sy - aScr[1]) <= HIT_PX) return { kind: 'anchor', name: 'anchor' };
```

`core/element.mjs:67` 的 `applyMatrix(m, p)` 返回的是 **`{ x, y }` 对象**；`toScreenArr` 取 `a[0] / a[1]` 是给 `elementLattice().map()` 那种 `[x, y]` 数组用的（见 `element.mjs:171`）。于是 `aScr[0]` / `aScr[1]` 都是 `undefined`，`Math.hypot(NaN, NaN)` 得 `NaN`，`NaN <= 9` 为 `false` —— **锚点永远不命中**。

改为：

```js
const aScr = toScreen(applyMatrix(elementWorldMatrix(el, time, size0, parentM), anchorPoint(el, size0)));
const onAnchor = pickAnchor(aScr, { x: p.sx, y: p.sy }, HIT_PX);
if (onAnchor) return onAnchor;
```

`pickAnchor`（`core/gizmo.mjs:167`）单独成函数是为了让「锚点优先于 8 个手柄」这条规则可测：锚点默认在 `(0,0)`，与 `nw` 手柄完全重合，若交给 `pickHandle` 一并判，同距时手柄先返回，用户就永远拖不到原点。

### 2.2 反解走了 `worldToLocal`（指针一离开对象就丢帧）

原 anchor 分支用 `worldToLocal(doc, el, t, p, parentM)` 反解局部坐标，它内部是 `latticeInverse`（`core/lattice.mjs:267`）：

- 先用**包围盒外扩 `pad = 2` 像素**做粗筛，点落在这个外扩框之外直接返回 `null`（`lattice.mjs:271-273`）；
- 再对每个 cell 跑牛顿迭代（`quadInverseLocal`），回代校验 `bestD <= Math.max(1.5, pad)`（`lattice.mjs:292`）。

实测（`_w4-probe-worldtolocal.mjs`，900×640、锚点 0/0、单位矩阵）：

| 局部坐标 | `worldToLocal` |
| --- | --- |
| `(0, 0)` 对象角 | `{u:0, v:0}` |
| `(-1, -1)` 对象外 1px | `{u:0, v:0}` |
| `(-3, -3)` 对象外 3px | **`null`** |

结论：**它的问题不是「边界不收敛」，而是「一离开对象就 `null`」**。拖锚点恰恰要让指针自由移动（想把原点推到边上、或从角上往里拖），只要指针跑出对象 2px 以上，反解就变 `null`，那一帧被 `if (!uv) return;` 丢弃，预览卡住不动。

还有两笔附带成本：锚点只需要**一次矩阵除法**，没必要每帧跑网格迭代；而且 `latticeInverse` 返回的是 **warp 之后**的网格 uv，`anchorPoint` 用的却是未 warp 的 `size * a` —— 对象带网格变形时两者不是一回事，混用会把网格偏移算进锚点。

改为直接在世界矩阵的逆空间里除基准尺寸（`core/gizmo.mjs:189` 的 `anchorUvFromMatrix`）：

```js
const inv = invertMatrix(elementWorldMatrix(el, t, drag.size, drag.parentM));
const uv = anchorUvFromMatrix(inv, drag.size, toDocPoint(e));
if (!uv) return;
preview = { elId: el.id, u: uv.u, v: uv.v };
```

它与 `anchorPoint(el, size)` 的 `size * a` **严格互逆**，越界统一夹到 `[0,1]`，没有任何容差或网格分支 —— 压在角上能拿到 `(0,0)`，拖到对象外 50px 也能拿到夹取后的边界值（`tests/canvas-anchor.test.mjs` 第 8 例用 `worldToLocal` 作对照钉住了这个差别）。

## 3. 交互契约

| 项 | 行为 | 落点 |
| --- | --- | --- |
| 命中优先级 | 锚点 > 变换手柄 > 对象本体 > 空白 | `canvas-input.mjs:59`（`pickAnchor` 先于 `hitAt` 里的 `pickHandle`） |
| 命中半径 | `HIT_PX = 9` 屏幕像素，**不随 zoom 变小**（手柄与锚点都按屏幕像素判） | `core/gizmo.mjs:38` |
| 视觉 | 十字准星 ±6px + 中心小圆点；锚点与 `nw` 手柄重合时靠圆点区分 | `canvas.mjs:369-383` |
| 拖动中 | 只画**虚线预览**十字，文档一个字都不写 | `canvas-input.mjs:151`、`canvas.mjs:363` |
| 松手 | 只 `setAnchor(id, uv, { keepPlace: true })` 一次 | `canvas-input.mjs:217` |
| Esc | 取消整次拖动，十字退回原位，什么都不写 | `canvas-input.mjs:111` 的 `onDragKeyDown` |
| 撤销粒度 | 一次拖动 = **一条**记录（由 `setAnchor` 内部那次 `setDoc` 生成，label「改旋转原点」） | `canvas-input.mjs:214-229` |
| 画板/设置 | 整段不生效：`drawGizmo` 在 `engine.isDrawingBoard()` 时直接短路 | `canvas.mjs:247` |

`keepPlace` 的语义（`app/shell/app.mjs:665`）：改原点时按 `d0 = (cur - next) * size` 反算位移，再叠到关键帧的 `x/y` 上，所以**对象在画面上不会因为改原点而跳位**。

## 4. 真机取证（Chromium / Edge，CDP 9334）

### 4.3 与属性面板入口的关系

两条入口写的是**同一个字段** `obj.anchor`，互相覆盖、没有第二份状态：

- 画布拖动：松手时 `ctx.setAnchor(id, {u,v}, { keepPlace: true })`（`canvas-input.mjs:225`）。
- 面板数字框 / 「居中」：`app/shell/app.mjs:665` 的同一个 `setAnchor`，`keepPlace` 由面板自己决定（数字框给 `true`，居中给 `false`）。

`keepPlace` 会把「原点变了多少」折算成位移补进关键帧的 `x/y`（`d0 = (cur - next) * size`），所以**改原点不会让内容在画面上跳位** —— 画布拖动与面板输入在这点上行为一致。差异只有一处：画布拖动把 uv **夹在 `[0,1]`**（原点始终落在对象矩形的边上或内部），面板数字框按 `0..100` 百分比的 `min/max` 夹，两者等价。

**不提供隐藏修饰键切换 `keepPlace`**（曾评估「按住 Alt 拖 = 不保持位置」，决定不做）：画布拖动与面板数字框必须同语义，多一个只在按住时才生效的修饰键，会让「为什么这次对象跳了」变成玄学 —— 要保持位置就这一条路，要跳位就用面板的「居中」（它走 `keepPlace: false`）。

## 5. 测试

新增 `tests/canvas-anchor.test.mjs`（9 例，纯 Node、零 DOM）：

1. `pickAnchor`：半径内命中、恰在 `HIT_PX` 上命中、超出 `+0.5` 放行、`HIT_PX >= 6` 的下限、自定阈值优先。
2. `pickAnchor`：锚点坐标缺失或非数值返回 `null`（防的正是 2.1 那个 `undefined` 现场），`[x,y]` 数组风格不会被误判成命中。
3. **优先级**：同一点上 `pickHandle` 给出 `scale/nw`，`pickAnchor` 给出 `anchor`；锚点移开后 `pickHandle` 照常返回 `nw`。
4. `anchorUvFromMatrix`：与 `size * a` 严格互逆（中心/四角）、越界夹到 `[0,1]`。
5. `anchorUvFromMatrix`：缩放 2× + 旋转 90° + 平移的矩阵下往返误差 `< 1e-9`。
6. `anchorUvFromMatrix`：与真实 `elementMatrix` / `anchorPoint` 闭环——锚点在 `(0,0)` 时反解必须成功。
7. `anchorUvFromMatrix`：`null` 矩阵、退化尺寸 `w=0`/`h=0`、`NaN` 输入一律 `null`，不产生 `NaN` 坐标。
8. **zoom 无关**：`pickAnchor` 在 zoom 1 / 2 / 0.5 下对同一屏幕偏移判定一致；反证组用 `HIT_PX * 0.5` 演示「阈值跟着 zoom 缩」会让 50% 缩放下点不到原点。
9. **对照 `worldToLocal`**：对象外 50px 处 `worldToLocal` 返回 `null` 而 `anchorUvFromMatrix` 给 `{u:0,v:0}`；对象外 1px 处两者都正常 —— 直接钉住 2.2 的换用理由。

## 6. 与任务描述不符的事实（如实记录）

1. **`core/gizmo.mjs` 里原本没有任何 anchor 相关代码**。任务描述说「gizmo.mjs 里已有 anchor 的几何与命中谓词」——不成立；原本只有 8 手柄与旋转柄的 `handlePositions` / `pickHandle`，锚点的几何在 `canvas-input.mjs` 里用 `elementWorldMatrix + anchorPoint` 现算。
2. **`#64` 的记录已过时**。它把问题写成「不能拖」，实际是「能拖但命中不到 + 起步丢帧」，两者修法不同（不是新加功能，是修坐标形状与容差）。
3. **没有 Shift 契约**。`canvas-input.mjs` 与 `core/gizmo.mjs` 里不存在任何 `shiftKey` 分支（全仓的 Shift 只用在时间轴/曲线编辑器的多选与吸附）。所以本次没有为锚点拖动发明「Shift 等比」之类行为。
4. **画板工作区里本来就没有选中概念**（`doc-state.mjs:175` 的 `isDrawingBoard()`、`canvas.mjs:247` 的短路、`app.mjs:1069` 的注释）。锚点拖动因此只在「编排」工作区可用，这不是本次引入的限制。

## 7. 遗留

- `core/element.mjs:236` 的 `hitTest` 走 `worldToLocal`，同样受 2.2 那套 1e-3 容差影响：指针恰好压在对象边界上时「点本体选中」可能落空。**不影响锚点**（锚点走纯距离判定），但属于同一族缺陷，可另开一条。
- 锚点吸附（对齐到对象中心/边、跨对象对齐线）未做。现在的行为是「拖到哪就是哪，夹在 `[0,1]`」。
- 触屏/手写笔未单独验证，走的是同一套 PointerEvent 路径。
