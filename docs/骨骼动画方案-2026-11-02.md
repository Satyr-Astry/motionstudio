# 骨骼动画方案（2026-11-02）

> 这份文档回答一个问题：**在现有时间驱动模型上做骨骼动画，需要新建什么、不需要新建什么。**
> 结论是**不需要新渲染器**——四阶段里最重的一块（LBS 蒙皮求值）已经在 `0.5.0-alpha.21` 落地。

## 1. 结论

已经有的（占九成）：

| 能力 | 在哪 |
| --- | --- |
| 对象层级与父链变换 | `app/core/evaluator.mjs` 的 `matrixOfChain`（自根向叶逐级相乘，每级用自己的局部时间与尺寸）、`elementMatrix` |
| 每对象独立时间轴 | `localTimeOf` / `applyTime`，父级的时间通道会作用到整棵子树 |
| 网格变形 | `app/core/lattice.mjs`（`pts` 是相对基准矩形的像素偏移）+ `paintWarped` 逐 cell 两三角形贴图 |
| 关键帧与贝塞尔 | `transform.keys`、`createKey`、`stateAt` |
| 导出与存档 | `.msp` 白名单序列化、PNG 序列 / 精灵图 / WebM |

缺的三件（就是这套方案的全部工作量）：

1. **一种不占纹理的对象类型**——骨骼要能建、能画、能选中，但它没有位图。
2. **顶点 → 骨骼的权重表**，以及绑定姿态快照。
3. **权重编辑的交互**（怎么让人把权重刷出来）。

## 2. 定位改写

从「面向独立游戏与前端演示的 2D 素材与短动效工厂」→ **「2D 角色与特效动画工具：纹理作画、时间驱动、骨骼装配」**。

服务三类：独立游戏 2D 美术（要能出帧表和精灵图）、前端与设计（做插画式动效）、内容作者（做透明短动图）。

明确不服务：影视后期、3D、逐帧像素手绘。矢量 UI 原型从「不做」松到「P1 之后勉强可做」。

## 3. 数据模型

### 3.1 骨骼对象

`kind: 'bone'`（第三个合法值，原有两个是 `'paint'` / `'image'`）+ 字段 `bone: { len, width, color }`。

定稿缺省（`app/core/doc-model.mjs` 的 `BONE_DEFAULTS` / `BONE_ANCHOR`）：

- `BONE_DEFAULTS = { len: 120, width: 14, color: '#7d8fa8' }`
- `BONE_ANCHOR = { x: 0, y: 0.5 }`（骨骼的旋转轴在根部，不在中心）

夹取而不是丢弃：`len ∈ [8, 4096]`、`width ∈ [2, 256]`，越界夹取；`color` 只认 `#rgb` / `#rrggbb`。

**必须同时改 `elementSize`**：`app/core/element.mjs` 的 `elementSize` 原本「优先纹理位图尺寸、取不到回退文档尺寸」，骨骼没有纹理，回退到 800×600 是错的——要加 bone 分支返回 `{ w: len, h: width }`。⚠️ `app/core/evaluator.mjs` 里还有一份自己的 `sizeOf`，**两份都要改**。P2-A 期间漏了这一处，导致同一根骨在两个模块里的世界矩阵差 293px 平移（`(0,300)` vs `(0,7)`），当时因为骨骼不绘制不命中所以没暴露，一绑权重整块皮肤错位。

### 3.2 蒙皮

- `skin.grid = { cols, rows }` —— 与 lattice 同密度，顶点数 = `(cols+1)*(rows+1)`
- `skin.bones = [{ id, bind: [a,b,c,d,e,f] }]` —— `bind` 是骨骼在绑定时刻的世界矩阵快照
- `skin.pts = [[{ b, w }, ...], ...]` —— 逐顶点权重，按顶点序号与 `lattice.pts` 一一对应

三条硬约束：

1. **`bind` 存世界矩阵快照，不存时间戳。** 存时刻的话，绑定后一动时间轴整块皮肤就散——「绑定」的语义是「这一刻的骨头位置是皮肤的家」，必须是数据而不是引用。
2. **权重按顶点序号与 `lattice.pts` 严格一一对应**，两边密度必须相等。不等时按 `latticeOffset` 重采样（`normalizeSkin` 不重采样，只在 `applySkin` 里做）。
3. **skin 模式下对象不把 `parentId` 指向骨骼。** 否则 `worldMatrix` 与蒙皮各乘一次 = 双重变形。UI 层必须拦（`app/editors/tree.mjs` 的 `parentBlocked()`，P2-B 已落地，带测试）。

每顶点权重上限 4（`SKIN_MAX_BONES_PER_POINT = 4`），超过按大小取前 4 再归一。

### 3.3 序列化：`.msp` 仍是 v4，不升版

判据是**读侧白名单会丢弃未知键**：v4 的读侧 `elementShell` 只认自己列的字段，所以老存档（没有 `bone`/`skin`）读进来照常工作、不需要迁移；新存档被 v4 读侧读到时不会崩，只是这两个字段会被丢掉。

代价是**降级会丢数据而不是报错**。这条已写在 `project-store.mjs` 的 `VERSION` 注释里。两个白名单（`elementToJSON` 与 `elementShell`）都必须加 `bone` / `skin` 段——**这是踩过两次的同一个坑**：白名单构造器会静默吃掉没加进去的字段（`effects` 一次、`skin` 一次）。

## 4. 蒙皮数学（LBS）

对第 i 个顶点、当前时刻 t：

- `rels[k] = M_k(t) · B_k⁻¹` —— 骨骼 k 相对绑定姿态的变换
- `W_i = Σ_k w_k · rels[k] · P_i` —— 权重混合后的世界位置（Σw 归一）
- `Q_i = worldMatrix(layer, t)⁻¹ · W_i`
- `off_i = Q_i − P_i` —— 填进 `lattice.pts[i]`

**为什么是 `worldMatrix⁻¹` 而不是 `parentMatrix⁻¹`**：`drawOne` 先 `g.transform(rec.matrix)` 再在局部空间画 `P + off`，所以局部偏移要用「世界 → 该对象局部」的逆，而 `rec.matrix` 正是 `worldMatrix`。

三条实现细节（`app/core/skin.mjs` 已按此实现，`tests/skin.test.mjs` 34 条对拍）：

- **失效骨跳过并重归一剩余权重**。不重归一会让 Σw < 1，仿射组合把皮肤拉向原点，表现成「删一根骨就缩小」。
- **Σw ≤ 1e-12 当纯 warp，不产 NaN。**
- **`st.warp` 全程只读**。用户的 warp 是落盘数据、蒙皮偏移是求值产物不落盘；两者逐顶点**相加**。

## 5. 四阶段

### P1 骨骼即对象 ✅ 已发 `0.5.0-alpha.20`

骨骼走同一套 transform 通道与父链，所以「建骨 → 调形 → 挂层级」当天就能做骨架动画，零求值代码。

施工规格（落点与验收口径）：

| 项 | 值 |
| --- | --- |
| 判别 | `kind === 'bone'`（`makeObject` 三分支白名单） |
| 字段 | `bone: { len, width, color }`，`normalizeBone` 归一 |
| 缺省 | `len 120 / width 14 / color #7d8fa8` |
| 夹取 | `len [8,4096]`、`width [2,256]`，越界夹不丢弃 |
| 锚点 | `BONE_ANCHOR = {0, 0.5}`（根部） |
| 尺寸 | `elementSize` 与 `evaluator.sizeOf` **两处**都要有 bone 分支 |
| 绘制 | `app/editors/canvas.mjs` 的 `drawBones(g)`，常显；选中不透明、未选中 0.42 |
| 命中 | `hitTest` 对 bone 单独放行（否则「看得见点不中」） |
| 落盘 | 两个白名单都写；`.msp` 仍 v4 |
| 字段隔离 | 骨骼不参与 `effects` / `skin`（它是驱动器） |

为什么要常显：骨骼没有位图，不画就等于不存在；而它的意义正是「看不见的骨架」，所以不能只在选中时画。

### P2-A 蒙皮求值 ✅ 已发 `0.5.0-alpha.21`

`app/core/skin.mjs`（500 行纯函数）：`normalizeSkin` / `skinOf` / `resampleWeights` / `boneMatrices` / `autoWeights` / `bindSkin` / `applySkin(doc, layer, lattice, matrix, size, t)`。

改动面只有一处：`evaluator.mjs` 的 `evalLayer` 算完 lattice 之后插一步 `const skinned = skinOf(layer) ? applySkin(...) : lattice;`。`worldMatrix` / `localTime` / `paintWarped` / `elementQuad` / `hit-mask` 全不改。

**import 方向是钉死的**：`skin.mjs` 不许 import `evaluator.mjs`（会成环），骨骼世界矩阵用 `elementMatrix` + 沿 parentId 自算（重复那十行是有意的，代码里有注释）。

### P2-B 绑定与父链拦截 ✅ 已发 `0.5.0-alpha.22`

- 命令 `object.bind-skin` / `object.unbind-skin`（走 `patchObject` → `setDoc`，一步撤销）。
- 父链拦截：`app/editors/tree.mjs` 的 `parentBlocked(doc, movedId, targetId)`；`dragover` 给 `drop-invalid` 且不 `preventDefault`，`drop` 早退并明确提示。
- 面板蒙皮段：只读摘要 + 解除绑定按钮。
- 同批删掉 `tree.mjs` 的假兜底 `setParentOf`——它调 `ctx.setParent`，而 ctx 上从来只有 `setLayerParent`，那个降级分支永远进不去。

### P2-C 步 1 蒙皮顶点可见与可选中 ✅ 已发 `0.5.0-alpha.24`

- `app/core/weight-paint.mjs`（纯 core）：`skinVertices(doc,el,t,parentM)` 用 `applySkin` 喂同密度 `createLattice` 走 same 分支拿逐顶点偏移、`weightSum`、`pickSkinVertex`、`WEIGHT_EPS`。
- `canvas.mjs` 的 `drawSkinWeights(g)` 排在 `drawBones(g)` 之后、`selectionInfo()` 判空之前；`canvas-input.mjs` 的 `hitAt` 顶部先问权重顶点，`onDown` 命中就 `preventDefault + stopPropagation` 直接 return。
- 面板蒙皮段加「编辑权重」开关与目标骨下拉。
- `state.weight = { active, layerId, boneId, vertex }`（**不落盘、不进撤销**）；多带 `layerId` 是因为换目标骨要先点骨骼、那一刻选区是骨骼，靠选区反查对象会让顶点当场消失。
- **同批修 `sameObjectPixels` 缺 `skin`**：不修则只改权重时 `commitDoc` 判「像素没变」、`scheduleRender` 不跑，「涂了没反应」而看着像命中坏了。这条是 P2-C 的第一行代码，不是笔刷。

### P2-C 步 2 刷权重与可视化 ✅ 已发 `0.5.0-alpha.25`

- `weight-paint.mjs` 105 → 360 行：`paintWeights(skin, hits, boneIndex, target, strength)`、`brushVertices`（**归一化参数空间**半径，缩放/旋转/非等比下手感一致）、`cachedSkinVertices`（单槽缓存：`el` 引用 + `el.skin` 引用 + `t` + 矩阵六元组）、`mainBoneIndex` / `boneColorOf` / `nearestBone`；`skin.mjs` 只把 `boneWorldMatrix`、`distToSegment` 加 `export`。
- 交互：`canvas-input.mjs` 的 `onDown` 接涂抹手势、`applyDrag` 每帧 `silent` 写入、`onDragEnd` 补**唯一**一条命令（`pushCommand` 优先、`history.push` 回落）、`Esc` 静默回滚。**全程不用 `coalesce`**。
- 视觉：顶点填充主骨色 + `globalAlpha = 0.45 + 0.55·mainW`、Σw≈0 画空心、目标骨加粗垫 `#ffd479`（权重态下 ACCENT 已是笔刷圈颜色）、笔刷圈按参数空间 64 段椭圆采样（**不用 `g.arc`**）。
- **与 §3 设计稿的一处顺序修正**：`paintSlot` 是「先把其余骨截到 `SKIN_MAX_BONES_PER_POINT−1 = 3` 根并摊平，再算缩放」，不是「先写目标骨、最后交给 `normalizeSkin` 截 4 根」。按原顺序，顶点已有 4 根骨时新刷的目标骨（第 5 根）会被降序立刻截掉，表现为**刷半天界面毫无反应**。两者数学等价（都过 `normalizeSkin`），差别在中间态用户看不看得见。

### P2-C 步 3 剩下的一点（径向菜单与重心色，未排期）

当前可用路径是「属性面板开开关 → 下拉选目标骨 → 画布拖动」。径向菜单（右键选骨）与权重重心可视化属体验增强，不阻塞使用。

撤销：**逐帧 silent + 松手一条命令**，不能靠 `coalesce`（`DOC_GESTURE_MS` 是 350ms，刷得慢会被合并，粒度随手感漂移）。

### P3 IK 待施工（风险最高，放最后）

解算结果**只进渲染矩阵，不回写关键帧**——回写会让「动一下骨头就产生一堆关键帧」，撤销栈与存档都被污染。要改 `matrixOfChain`，所以它必须在 P2 全部稳定之后。

### P4 互操作 待施工

`.msp` 升 v5（若届时有需要）+ 导出每骨每帧矩阵。**不做** Spine / DragonBones 导入（格式差异大、收益低）。
